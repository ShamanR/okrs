# Proposal: longer-slugs-and-demo-seeding

## Why

Slug пространства ограничен 32 символами — это мало для красивых и разнообразных алиасов.
Кроме того, каждое новое пространство создаётся пустым, и администратор вынужден вручную
настраивать структуру (периоды, команды, цели), прежде чем пространством можно пользоваться.
Демо-наполнение существует только в виде `seed_demo.sql` с захардкоженными датами 2026 года
и id сущностей — оно неприменимо к произвольному пространству и быстро устаревает.

## What Changes

- Максимальная длина slug увеличивается с 32 до 63 символов (потолок DNS label — slug
  участвует в поддоменной маршрутизации). Грамматика символов не меняется.
- При создании пространства оно автоматически наполняется демо-структурой: иерархия команд,
  периоды, цели, ключевые результаты и сопутствующие сущности — содержимое, соответствующее
  текущему `seed_demo.sql`.
- Периоды демо-наполнения вычисляются относительно даты создания: текущий год, его кварталы,
  предыдущий год. Никаких литеральных дат.
- Демо-наполнение переносится в SQL-функцию `seed_demo_data(tenant_id)`, создаваемую
  миграцией. Создание пространства и сидирование выполняются в одной транзакции.
- `seed_demo.sql` сокращается до тонкой обёртки для локального окружения (вызов функции для
  тенанта по умолчанию) — единственный источник правды о демо-данных остаётся один.
- Обновление демо-данных в уже существующих пространствах НЕ входит в скоуп: устаревание
  периодов со временем принимается.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `tenancy`: меняется валидация slug (максимум 63 символа вместо 32); создание пространства
  дополняется обязательным демо-наполнением с периодами, актуальными на дату создания.

## Impact

- Код: `internal/core/domain/tenant.go` (валидация slug), `internal/service/provisioning`
  (сидирование при создании), слой store — выполнение SQL-функции в транзакции создания.
- Миграции: новая миграция с функцией `seed_demo_data(tenant_id bigint)`.
- `seed_demo.sql` — сокращается до вызова функции; хаки `ALTER TABLE ... SET DEFAULT 1` и
  глобальный `TRUNCATE` уходят из рантайм-пути.
- UI: подсказки/валидация длины slug, если где-то захардкожено «32».
- Кастомное сообщение «нет доступа» (`no_access_message`) — НЕ затрагивается: механизм уже
  существует и признан достаточным.
