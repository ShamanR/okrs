## MODIFIED Requirements

### Requirement: Фильтр доски по приоритету

Система ОБЯЗАНА предлагать фильтр целей по приоритету в блоке управления показом целей,
когда у команды в периоде есть хотя бы одна цель. У каждого уровня приоритета ОБЯЗАНО
отображаться число целей этого уровня в периоде. Уровень без целей ОБЯЗАН быть недоступен
для выбора.

Выбор одного или нескольких уровней ОБЯЗАН сужать список показанных целей. Когда выбран хотя
бы один уровень, ОБЯЗАН отображаться элемент сброса фильтра.

Фильтр ОБЯЗАН сужать только показ. Прогресс команды, сумма весов целей, охват выгрузки и
вычисление занятого веса в окне цели ОБЯЗАНЫ считаться по всем целям периода независимо от
фильтра.

#### Scenario: Фильтр сужает показ

- GIVEN у команды две цели приоритета P1 и одна P2
- WHEN пользователь выбирает P1
- THEN на доске показаны две цели, а элемент сброса фильтра доступен

#### Scenario: Уровень без целей

- GIVEN у команды нет целей приоритета P0
- WHEN пользователь открывает доску
- THEN уровень P0 показан со счётчиком ноль и недоступен для выбора

#### Scenario: Фильтр не влияет на расчёты

- GIVEN у команды две цели весом 50% каждая, выбран фильтр по одному приоритету
- WHEN пользователь смотрит доску
- THEN предупреждение о нарушенной сумме весов целей не отображается

#### Scenario: Фильтр находится не в шапке доски

- GIVEN у команды есть цели
- WHEN пользователь открывает доску
- THEN фильтр по приоритету показан в блоке управления показом целей, а не в шапке доски

### Requirement: Меню действий цели и ключевого результата

Система ОБЯЗАНА предлагать у цели и у ключевого результата меню действий в постоянной позиции
строки. Меню цели ОБЯЗАНО содержать редактирование, копирование ссылки, перенос или копирование
в другую команду либо период, выгрузку в Markdown и удаление. Меню ключевого результата ОБЯЗАНО
содержать редактирование, копирование ссылки и удаление, а у ключевого результата с заметкой —
также переключение показа заметки.

Пункт меню, недоступный в текущем режиме редактирования, ОБЯЗАН оставаться в списке, нести
признак недоступности и объяснять причину — текущий статус команды в периоде. Активировать
такой пункт НЕОБХОДИМО не допускать.

Перенос цели в другую команду или период убирает её из состава целей текущей команды, поэтому
режим переноса ОБЯЗАН быть недоступен и называть статус причиной, когда полное редактирование
закрыто. Копирование цели состав текущей команды не меняет и ОБЯЗАНО оставаться доступным во
всех статусах; когда перенос недоступен, пункт меню ОБЯЗАН называть только копирование.

Пункт меню, копирующий что-либо в буфер обмена, ОБЯЗАН сообщить результат на себе же и только
после этого закрывать меню — и при успехе, и при отказе буфера.

#### Scenario: Недоступный пункт объясняет причину

- GIVEN команда в статусе «в работе»
- WHEN пользователь открывает меню действий цели
- THEN пункты изменения состава целей остаются в списке, помечены недоступными и называют
  статус команды причиной

#### Scenario: Недоступный пункт не срабатывает

- GIVEN команда в статусе «закрыт»
- WHEN пользователь активирует недоступный пункт меню
- THEN действие не выполняется и окно не открывается

#### Scenario: Перенос недоступен, копирование доступно

- GIVEN команда в статусе «в работе»
- WHEN пользователь открывает из меню цели окно переноса
- THEN режим «перенести» помечен недоступным и называет статус причиной, а режим
  «скопировать» доступен

#### Scenario: Копирование ссылки подтверждается

- GIVEN пользователь открыл меню действий цели
- WHEN он выбирает копирование ссылки и буфер обмена принимает значение
- THEN пункт подтверждает копирование, и только после этого меню закрывается

#### Scenario: Буфер обмена отказал

- GIVEN пользователь выбрал копирование ссылки
- WHEN буфер обмена отклоняет запись
- THEN пункт сообщает, что скопировать не удалось, а не закрывается молча

#### Scenario: Переключение заметки есть только у ключевого результата с заметкой

- GIVEN у одного ключевого результата цели есть заметка, у другого нет
- WHEN пользователь открывает меню действий каждого из них
- THEN пункт переключения показа заметки есть только в меню первого

## ADDED Requirements

### Requirement: Блок управления показом целей

Система ОБЯЗАНА показывать на доске команды блок управления показом целей между шапкой доски
и списком целей команды. Блок ОБЯЗАН содержать выбор порядка целей, фильтр по приоритету,
переключатель показа заметок к ключевым результатам и переключатель скрытия целей с нулевым
весом.

Блок ОБЯЗАН отображаться, когда у команды в периоде есть хотя бы одна цель. У команды без
целей блок отображать НЕОБХОДИМО не допускать: управлять показом нечем, а доска в этом
состоянии предлагает создать первую цель.

Когда хотя бы одна настройка блока отличается от значения по умолчанию, блок ОБЯЗАН
предлагать сброс всех настроек к значениям по умолчанию.

Настройки блока ОБЯЗАНЫ влиять только на показ. Прогресс команды, прогресс цели, сумма весов
целей, предупреждение о нарушенной сумме весов, охват выгрузки и вычисление занятого веса в
окне цели ОБЯЗАНЫ считаться по всем целям периода независимо от настроек блока.

#### Scenario: Блок находится между шапкой и целями

- GIVEN у команды есть цели
- WHEN пользователь открывает доску
- THEN блок управления показом показан над списком целей команды и ниже шапки доски

#### Scenario: Команда без целей

- GIVEN у команды в периоде нет целей
- WHEN пользователь открывает доску
- THEN блок управления показом не отображается

#### Scenario: Сброс настроек

- GIVEN пользователь выбрал порядок по приоритету, уровень приоритета и скрытие целей с
  нулевым весом
- WHEN он выполняет сброс настроек блока
- THEN порядок целей снова пользовательский, фильтр по приоритету снят, оба переключателя
  выключены

#### Scenario: Сброс не предлагается при значениях по умолчанию

- GIVEN все настройки блока имеют значения по умолчанию
- WHEN пользователь смотрит блок
- THEN элемент сброса не отображается

#### Scenario: Настройки не влияют на прогресс команды

- GIVEN у команды четыре цели, из них одна с нулевым весом
- WHEN пользователь включает скрытие целей с нулевым весом
- THEN прогресс команды в шапке доски не изменяется

### Requirement: Порядок целей на доске

Система ОБЯЗАНА предлагать два порядка целей на доске: пользовательский и по приоритету.
Пользовательский порядок — порядок, заданный перетаскиванием целей, — ОБЯЗАН быть значением
по умолчанию.

Порядок по приоритету ОБЯЗАН выстраивать цели от высшего приоритета к низшему. Цели одного
приоритета ОБЯЗАНЫ сохранять между собой пользовательский порядок.

Порядок ОБЯЗАН менять только показ: порядок целей, сохранённый у команды в периоде, выбором
порядка на доске не меняется.

Перетаскивание целей меняет пользовательский порядок, поэтому при порядке по приоритету
перетаскивание целей ОБЯЗАНО быть недоступно, а средство перетаскивания цели — не
отображаться. Перетаскивание ключевых результатов внутри цели ОБЯЗАНО оставаться доступным
на тех же условиях, что и раньше.

#### Scenario: Порядок по приоритету

- GIVEN у команды цели в пользовательском порядке P2, P0, P1
- WHEN пользователь выбирает порядок по приоритету
- THEN цели показаны в порядке P0, P1, P2

#### Scenario: Цели одного приоритета сохраняют пользовательский порядок

- GIVEN у команды две цели приоритета P1, идущие в пользовательском порядке одна за другой
- WHEN пользователь выбирает порядок по приоритету
- THEN эти две цели идут в том же относительном порядке

#### Scenario: Сохранённый порядок не меняется

- GIVEN пользователь выбрал порядок по приоритету
- WHEN он возвращает пользовательский порядок
- THEN цели показаны в том же порядке, что и до выбора порядка по приоритету

#### Scenario: Перетаскивание недоступно при порядке по приоритету

- GIVEN пользователю доступно изменение порядка целей
- WHEN он выбирает порядок по приоритету
- THEN средство перетаскивания цели не отображается, а перетащить цель нельзя

#### Scenario: Перетаскивание ключевых результатов не затронуто

- GIVEN пользователю доступно изменение порядка и выбран порядок по приоритету
- WHEN он перетаскивает ключевой результат внутри цели
- THEN порядок ключевых результатов цели меняется

### Requirement: Скрытие целей с нулевым весом

Система ОБЯЗАНА предлагать скрыть с доски цели с нулевым весом. По умолчанию такие цели
ОБЯЗАНЫ отображаться.

Скрытие ОБЯЗАНО сужать только показ: предупреждение о нарушенной сумме весов целей,
прогресс команды и охват выгрузки ОБЯЗАНЫ считаться по всем целям периода, включая скрытые.

#### Scenario: Цели с нулевым весом скрыты

- GIVEN у команды три цели, у одной из них вес 0%
- WHEN пользователь включает скрытие целей с нулевым весом
- THEN на доске показаны две цели

#### Scenario: Скрытие не влияет на предупреждение о сумме весов

- GIVEN у команды цели с суммой весов 100%, одна из них весом 0%
- WHEN пользователь включает скрытие целей с нулевым весом
- THEN предупреждение о нарушенной сумме весов целей не отображается

#### Scenario: По умолчанию цели с нулевым весом видны

- GIVEN пользователь ни разу не менял настройки блока управления показом
- WHEN он открывает доску команды, у которой есть цель весом 0%
- THEN эта цель показана

### Requirement: Показ заметок к ключевым результатам на доске

Система ОБЯЗАНА показывать заметку ключевого результата в строке ключевого результата на
доске, когда показ заметки включён. Ключевой результат без заметки ОБЯЗАН не показывать ни
заметку, ни средство её переключения.

Система ОБЯЗАНА предлагать в блоке управления показом переключатель, включающий показ заметок
сразу у всех ключевых результатов на доске. По умолчанию заметки ОБЯЗАНЫ быть скрыты.

Переключение показа заметки у отдельного ключевого результата ОБЯЗАНО перекрывать общий
переключатель для этого ключевого результата. Переключение общего переключателя ОБЯЗАНО
сбрасывать такие перекрытия: после него показ заметок у всех ключевых результатов
соответствует общему переключателю.

Показанная заметка ОБЯЗАНА отображаться полностью. Заметку, не помещающуюся в одну строку,
пользователь ОБЯЗАН иметь возможность свернуть до одной строки и развернуть обратно
нажатием на саму заметку; скрывать заметку это действие НЕОБХОДИМО не допускать — скрытие
выполняется только из меню действий ключевого результата.

Показ заметки ОБЯЗАН не зависеть от режима редактирования: заметка видна и в закрытом
периоде.

#### Scenario: Заметки показаны по всей доске

- GIVEN у команды три цели, у части ключевых результатов есть заметки
- WHEN пользователь включает показ заметок
- THEN заметка показана у каждого ключевого результата, у которого она есть

#### Scenario: Ключевой результат без заметки

- GIVEN у ключевого результата нет заметки
- WHEN пользователь включает показ заметок
- THEN в строке этого ключевого результата заметка не появляется

#### Scenario: Сворачивание заметки не скрывает её

- GIVEN показ заметок включён, и заметка не помещается в одну строку
- WHEN пользователь нажимает на саму заметку
- THEN заметка свёрнута до одной строки и остаётся видимой, а повторное нажатие
  разворачивает её обратно

#### Scenario: Индивидуальное скрытие при включённом показе

- GIVEN показ заметок включён
- WHEN пользователь скрывает заметку одного ключевого результата из его меню действий
- THEN заметка этого ключевого результата скрыта, у остальных показана

#### Scenario: Общий переключатель сбрасывает индивидуальные перекрытия

- GIVEN показ заметок включён, и у одного ключевого результата заметка скрыта вручную
- WHEN пользователь выключает и снова включает показ заметок
- THEN заметка показана у всех ключевых результатов, у которых она есть

#### Scenario: Заметки в закрытом периоде

- GIVEN команда в статусе «закрыт»
- WHEN пользователь включает показ заметок
- THEN заметки ключевых результатов показаны

### Requirement: Сохранение настроек показа целей

Система ОБЯЗАНА сохранять настройки блока управления показом на стороне клиента и
восстанавливать их при открытии доски.

Настройки ОБЯЗАНЫ не зависеть от выбранной команды и периода: смена команды и смена периода
ОБЯЗАНЫ сохранять действующие настройки.

Сохранённое значение, которое невозможно истолковать, ОБЯЗАНО не приводить к ошибке:
система ОБЯЗАНА применять значения по умолчанию.

Отказ хранилища ОБЯЗАН не ломать доску: при невозможности сохранить настройки доска
ОБЯЗАНА продолжать работать с настройками, действующими в текущем отображении.

#### Scenario: Перезагрузка страницы

- GIVEN пользователь выбрал порядок по приоритету и включил показ заметок
- WHEN он перезагружает страницу
- THEN порядок по приоритету и показ заметок остаются включёнными

#### Scenario: Смена команды

- GIVEN пользователь выбрал уровень приоритета и включил скрытие целей с нулевым весом
- WHEN он переключается на другую команду
- THEN выбранный уровень приоритета и скрытие целей с нулевым весом остаются в силе

#### Scenario: Смена периода

- GIVEN пользователь включил показ заметок
- WHEN он выбирает другой период
- THEN показ заметок остаётся включённым

#### Scenario: Повреждённые сохранённые настройки

- GIVEN в клиентском хранилище лежит значение настроек, которое невозможно истолковать
- WHEN пользователь открывает доску
- THEN доска открывается с настройками по умолчанию и без ошибки

### Requirement: Цель по прямой ссылке не скрывается настройками показа

Система ОБЯЗАНА показывать цель, на которую ведёт открытая прямая ссылка, независимо от
действующих настроек показа, и выполнять переход к ней. Прокрутку к цели, скрытой
настройками показа, молча не выполнять НЕОБХОДИМО не допускать.

Настройки показа при этом ОБЯЗАНЫ сохраняться: открытие прямой ссылки их не сбрасывает.

Закрепление ОБЯЗАНО действовать до первого изменения настроек показа пользователем. После
того как пользователь сам изменил настройки, цель по ссылке ОБЯЗАНА подчиняться им, как и
остальные.

#### Scenario: Цель по ссылке скрыта фильтром

- GIVEN в сохранённых настройках показа выбран приоритет P0
- WHEN пользователь открывает прямую ссылку на цель приоритета P2
- THEN цель показана на доске, выполнены переход к ней и подсветка, а выбранный уровень
  приоритета остаётся в настройках

#### Scenario: Пользователь берёт управление на себя

- GIVEN цель показана по прямой ссылке вопреки настройкам показа
- WHEN пользователь меняет любую настройку показа
- THEN цель перестаёт быть закреплённой и подчиняется настройкам наравне с остальными

### Requirement: Пустой результат фильтрации целей

Система ОБЯЗАНА сообщать, что ни одна цель команды не подходит под действующие настройки
показа, когда у команды в периоде есть цели, но показать нечего. Сообщение ОБЯЗАНО
предлагать сброс настроек показа.

Это состояние ОБЯЗАНО отличаться от состояния «у команды нет целей»: предложение создать
первую цель в нём отображать НЕОБХОДИМО не допускать.

#### Scenario: Фильтр скрыл все цели

- GIVEN у команды только цели приоритета P2, и все они весом 0%
- WHEN пользователь включает скрытие целей с нулевым весом
- THEN доска сообщает, что под настройки показа не подходит ни одна цель, и предлагает сброс

#### Scenario: Отличие от команды без целей

- GIVEN у команды есть цели, но настройки показа скрыли их все
- WHEN пользователь смотрит доску
- THEN предложение создать первую цель не отображается
