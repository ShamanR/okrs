## MODIFIED Requirements

### Requirement: Состав карточки цели

Система ОБЯЗАНА показывать на карточке цели заголовок, иконку направления, приоритет, вес, тип
работы, драйверов цели, описание цели, прогресс с отметкой ожидаемого темпа, ключевые
результаты и раскрываемый блок обсуждения. Описание цели ОБЯЗАНО отображаться с сохранением
разметки и в свёрнутом виде, если оно превышает ограничение по высоте.

Шапка карточки ОБЯЗАНА размещаться в одной строке и содержать в этом порядке: вес, приоритет,
иконку направления, заголовок со связями вверх и вниз, лейбл типа работы, драйверов, полосу
прогресса, процент прогресса и меню действий. Разносить эти сведения по нескольким строкам
НЕОБХОДИМО не допускать. Направление показывается только иконкой: отдельного текстового лейбла
направления в шапке нет.

Форма отображения драйверов в шапке определяется требованием «Имена драйверов уступают место
заголовку»: имена показываются, пока вмещаются без обрезания заголовка, а иначе уступают ему
место и остаются доступными по наведению.

Единственные раскрываемые элементы карточки — обсуждение и длинные описания. Прочие сведения
карточки ОБЯЗАНЫ быть видны без действий пользователя. Текст, не вместившийся по ширине,
раскрытием не считается: он ОБЯЗАН показываться целиком по наведению согласно требованию
«Полный текст обрезанного заголовка по наведению».

#### Scenario: Просмотр карточки

- GIVEN у цели заполнены метаданные и есть ключевые результаты
- WHEN пользователь открывает доску
- THEN на карточке отображаются метаданные, описание, прогресс и ключевые результаты, а
  раскрываемым остаётся только обсуждение

#### Scenario: Шапка в одной строке

- GIVEN у цели заполнены вес, приоритет, направление, тип работы и драйверы
- WHEN пользователь открывает доску
- THEN все эти сведения вместе с полосой прогресса и процентом отображаются в одной строке

#### Scenario: Иконка направления слева от заголовка

- GIVEN у цели направление «Техника»
- WHEN пользователь открывает доску
- THEN непосредственно слева от заголовка цели стоит иконка ⚙️, а лейбла с названием
  направления в шапке нет

#### Scenario: Цель без описания

- GIVEN у цели не заполнено описание
- WHEN пользователь открывает доску
- THEN на карточке не отображается ни блок описания, ни элемент разворачивания

### Requirement: Заголовок — главный текст карточки цели

Заголовок цели ОБЯЗАН читаться как главный текст шапки: он ОБЯЗАН быть крупнее любой другой
подписи шапки — веса, приоритета, иконки направления, лейблов, драйверов и процента прогресса.

Соседние карточки целей ОБЯЗАНЫ разделяться промежутком, по которому граница между двумя
целями читается без наведения и без выделения карточки.

Укрупнение заголовка НЕОБХОДИМО не допускать за счёт выноса шапки в несколько строк:
требование «шапка в одной строке» остаётся в силе.

#### Scenario: Заголовок выделяется среди подписей шапки

- **GIVEN** у цели заполнены вес, приоритет, направление, тип работы и драйверы
- **WHEN** пользователь открывает доску
- **THEN** заголовок цели читается крупнее остальных подписей шапки
- **AND** шапка остаётся в одной строке

#### Scenario: Границы между целями видны без наведения

- **GIVEN** на доске подряд идут несколько целей
- **WHEN** пользователь смотрит на список
- **THEN** он различает, где кончается одна цель и начинается следующая, не наводя курсор

### Requirement: Блок управления показом целей

Система ОБЯЗАНА показывать на доске команды блок управления показом целей между шапкой доски
и списком целей команды. Блок ОБЯЗАН содержать выбор порядка целей, фильтр по приоритету,
фильтр по направлению, переключатель показа заметок к ключевым результатам и переключатель
скрытия целей с нулевым весом.

Блок ОБЯЗАН отображаться, когда у команды в периоде есть хотя бы одна цель. У команды без
целей блок отображать НЕОБХОДИМО не допускать: управлять показом нечем, а доска в этом
состоянии предлагает создать первую цель.

Когда хотя бы одна настройка блока отличается от значения по умолчанию, блок ОБЯЗАН
предлагать сброс всех настроек к значениям по умолчанию.

Настройки блока ОБЯЗАНЫ влиять только на показ. Прогресс команды, прогресс цели, сумма весов
целей, предупреждение о нарушенной сумме весов, охват выгрузки и вычисление занятого веса в
окне цели ОБЯЗАНЫ считаться по всем целям периода независимо от настроек блока.

#### Scenario: Блок находится между шапкой и целями

- GIVEN у команды есть цели
- WHEN пользователь открывает доску
- THEN блок управления показом показан над списком целей команды и ниже шапки доски

#### Scenario: Команда без целей

- GIVEN у команды в периоде нет целей
- WHEN пользователь открывает доску
- THEN блок управления показом не отображается

#### Scenario: Сброс настроек

- GIVEN пользователь выбрал порядок по приоритету, уровень приоритета, направление и скрытие
  целей с нулевым весом
- WHEN он выполняет сброс настроек блока
- THEN порядок целей снова пользовательский, фильтры по приоритету и по направлению сняты, оба
  переключателя выключены

#### Scenario: Сброс не предлагается при значениях по умолчанию

- GIVEN все настройки блока имеют значения по умолчанию
- WHEN пользователь смотрит блок
- THEN элемент сброса не отображается

#### Scenario: Настройки не влияют на прогресс команды

- GIVEN у команды четыре цели, из них одна с нулевым весом
- WHEN пользователь включает скрытие целей с нулевым весом
- THEN прогресс команды в шапке доски не изменяется

## ADDED Requirements

### Requirement: Подсказка по иконке направления

Иконка направления цели ОБЯЗАНА по наведению указателя и при получении фокуса с клавиатуры
показывать подсказку с названием и описанием направления. Подсказка ОБЯЗАНА выглядеть и вести
себя одинаково везде, где показана иконка: на доске, в дереве целей, в обзоре периода и в
журнале активности.

#### Scenario: Наведение на иконку

- GIVEN у цели направление «Процессы»
- WHEN пользователь наводит указатель на иконку 📈 слева от заголовка
- THEN появляется подсказка «Процессы» с описанием «Эффективность, организация работы,
  автоматизация процессов»

#### Scenario: Фокус с клавиатуры

- GIVEN пользователь перемещается по доске клавишей Tab
- WHEN фокус попадает на иконку направления
- THEN подсказка показывается так же, как при наведении

### Requirement: Выбор направления в окне цели

Окно создания и редактирования цели ОБЯЗАНО предлагать выбор направления в той же строке и на
том же месте, где раньше был выбор фокуса: рядом с приоритетом и типом работы. Поле ОБЯЗАНО
называться «Направление цели».

Выбор направления ОБЯЗАН быть устроен так же, как выбор приоритета: закрытый элемент
показывает иконку и название выбранного направления, а раскрытый список показывает у каждого
направления иконку, название и описание и отмечает выбранное. Выбор варианта закрывает список.

#### Scenario: Раскрытый список направлений

- GIVEN пользователь открыл окно цели
- WHEN он раскрывает выбор направления
- THEN он видит три варианта в порядке Продукт, Техника, Процессы, у каждого иконка, название
  и описание, а текущий вариант отмечен

#### Scenario: Смена направления

- GIVEN у цели направление «Продукт»
- WHEN пользователь выбирает «Техника» и сохраняет цель
- THEN на карточке цели слева от заголовка стоит иконка ⚙️

### Requirement: Фильтр доски по направлению

Система ОБЯЗАНА предлагать фильтр целей по направлению в блоке управления показом целей, когда
у команды в периоде есть хотя бы одна цель. Каждое направление ОБЯЗАНО отображаться иконкой и
названием с числом целей этого направления в периоде. Направление без целей ОБЯЗАНО быть
недоступно для выбора.

Выбор одного или нескольких направлений ОБЯЗАН сужать список показанных целей. Когда выбрано
хотя бы одно направление, ОБЯЗАН отображаться элемент сброса этого фильтра.

Фильтр по направлению ОБЯЗАН сочетаться с фильтром по приоритету: показываются цели,
подходящие под оба фильтра. Выбранные направления ОБЯЗАНЫ сохраняться и восстанавливаться
вместе с остальными настройками показа и подчиняться правилам требований «Сохранение настроек
показа целей», «Цель по прямой ссылке не скрывается настройками показа» и «Пустой результат
фильтрации целей».

Фильтр ОБЯЗАН сужать только показ: прогресс команды, сумма весов целей, охват выгрузки и
вычисление занятого веса в окне цели ОБЯЗАНЫ считаться по всем целям периода.

#### Scenario: Фильтр сужает показ

- GIVEN у команды две цели направления «Продукт» и одна «Техника»
- WHEN пользователь выбирает «Продукт»
- THEN на доске показаны две цели, а элемент сброса фильтра по направлению доступен

#### Scenario: Направление без целей

- GIVEN у команды нет целей направления «Процессы»
- WHEN пользователь открывает доску
- THEN «Процессы» показано со счётчиком ноль и недоступно для выбора

#### Scenario: Сочетание с фильтром по приоритету

- GIVEN у команды цели «Продукт» P1, «Продукт» P2 и «Техника» P1
- WHEN пользователь выбирает направление «Продукт» и приоритет P1
- THEN на доске показана одна цель — «Продукт» P1

#### Scenario: Направление сохраняется при смене команды

- GIVEN пользователь выбрал направление «Техника»
- WHEN он переключается на другую команду или перезагружает страницу
- THEN фильтр по направлению «Техника» остаётся в силе
