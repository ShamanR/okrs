## Why

Сейчас у цели есть «фокус» с четырьмя значениями: Profitability, Stability, Speed Efficiency,
Tech Independence. Границы между ними неочевидны: одна и та же цель подходит под два-три
значения, поэтому команды выбирают наугад, а балансы в обзоре периода мало что говорят.

Вместо фокуса вводим «направление цели» — три понятные категории:

- 🚀 **Продукт**: развитие функциональности, ценность для пользователей, бизнес-результаты;
- ⚙️ **Техника**: архитектура, надёжность, безопасность, техническое качество;
- 📈 **Процессы**: эффективность, организация работы, автоматизация процессов.

Направление должно быть видно там, где видна цель, и по нему должно быть удобно смотреть
баланс и фильтровать список целей.

## What Changes

- **BREAKING** Поле цели «фокус» заменяется полем «направление» с тремя значениями: Продукт,
  Техника, Процессы. Направление обязательно, у новой цели по умолчанию — «Продукт».
  Значения фокуса больше не принимаются.
- Существующие цели переводятся на направления по таблице: Profitability → Продукт,
  Stability → Техника, Speed Efficiency → Процессы, Tech Independence → Техника.
- В окне редактирования цели на месте выбора фокуса — выбор направления. Селектор устроен так
  же, как селектор приоритета: в раскрытом списке у каждого варианта видны иконка, название
  и описание.
- Иконка направления стоит слева от заголовка цели: на карточке цели на доске, на карточке и
  в панели деталей дерева целей, в списке целей при детализации обзора периода и в записях
  журнала активности, где упоминается цель. Лейбл фокуса на карточке убирается.
- Наведение на иконку (и фокус с клавиатуры) показывает подсказку: название и описание
  направления.
- В обзоре периода баланс «Стратегические фокусы» заменяется балансом «Направления целей» из
  трёх категорий. Детализация по клику работает как сейчас.
- В блоке управления показом целей на доске появляется фильтр по направлению. Он устроен как
  фильтр по приоритету: счётчик у каждого направления, множественный выбор, сохранение вместе
  с остальными настройками показа, сброс.
- Выгрузка целей показывает название направления вместо фокуса.
- **BREAKING (API)** Поле `focus_type` в запросах и ответах API целей, дерева целей и обзора
  периода заменяется полем `direction`, ключ баланса `focuses` — ключом `directions`. API
  используется только собственным фронтендом, который обновляется в том же изменении.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `goal-management`: поле цели «фокус» заменяется обязательным «направлением» из трёх
  значений; перевод существующих целей.
- `team-okr-board`: состав карточки цели (иконка направления вместо лейбла фокуса), подсказка
  по иконке, селектор направления в окне цели, фильтр по направлению в блоке управления
  показом.
- `period-overview`: баланс по направлениям вместо баланса по фокусам, иконка направления в
  списке целей детализации.
- `goal-tree-view`: иконка направления на карточке и в панели деталей цели.
- `activity-log`: иконка направления перед заголовком цели в записях журнала.

## Impact

- **БД**: новая миграция — колонка направления у `goals` с переводом значений фокуса; старая
  колонка `focus_type` удаляется отдельным изменением после выкладки (см. design.md).
- **Backend**: доменный тип направления вместо `FocusType`, валидация ввода цели, репозиторий
  целей (в том числе копирование цели), DTO и обработчики API целей, дерева целей и обзора
  периода, расчёт балансов обзора, лента журнала активности (направление цели одним запросом
  на страницу), выгрузка Markdown, `internal/store/seed.go`.
- **Frontend**: `web/static/ui.js` (общие константы направления и иконка с подсказкой),
  `tracker.js` / `tracker.css` (карточка, окно цели, фильтр), `goal_tree.js`,
  `period_overview_view.js`, `activity.js`.
- **Данные демо**: `seed_demo.sql`.
- **Тесты**: тесты, создающие цели с `FocusType`, и тесты валидации, балансов, выгрузки,
  ленты журнала.
- **Дизайн-система**: карточки `goal-card`, `goal-form`, карточки дерева целей и прототип.
- **Документация**: `README.md`, `docs/goals.md`, `docs/interface.md`.

Противоречий между текущими specs и кодом не обнаружено. Есть одно расхождение формулировок:
spec `period-overview` называет баланс «по фокусу», а интерфейс — «Стратегические фокусы»;
оба заменяются направлением.
