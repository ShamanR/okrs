# Proposal: per-tab-tenant-context

## Why

Активное пространство сегодня хранится в серверной сессии (`auth_sessions.active_tenant_id`),
одной на весь браузер. Из-за этого невозможно работать в двух пространствах в разных вкладках:
переключение в одной вкладке молча меняет контекст другой, и запросы из неё уезжают в чужое
пространство. Серверная сессия как носитель «текущего пространства» — состояние, общее для всех
вкладок по построению; заплатками это не лечится, нужно перенести контекст на клиент.

## What Changes

- Активное пространство передаётся каждым API-запросом явно — заголовком `X-Tenant-ID`.
  Сервер валидирует его против активных членств пользователя (постороннее значение → отказ).
- Клиент хранит контекст вкладки в `sessionStorage` (изолировано между вкладками), а «последний
  выбранный» — в `localStorage` (переживает перезапуск браузера). Переключение пространства
  становится чисто клиентским действием без записи на сервер.
- Серверный шелл становится tenant-agnostic: первый рендер не требует знания о пространстве,
  клиент после загрузки сам резолвит контекст (sessionStorage → localStorage → список членств).
- **BREAKING**: `auth_sessions.active_tenant_id` удаляется; `POST /api/v1/session/tenant`
  упраздняется как переключатель (сессия больше не несёт пространства).
- No-access и «нет членств» становятся клиентским состоянием: API сигналит отсутствие членства
  отдельным ответом, клиент показывает экран no-access вместо серверного редиректа.
- Tenant-резолв на сервере — новая стратегия `header` в существующей цепочке `TenantResolver`.

## Capabilities

### New Capabilities

- (пусто)

### Modified Capabilities

- `tenancy`: меняются требования к резолву и переключению активного пространства — источником
  истины становится заголовок запроса и клиентское хранилище вместо серверной сессии; серверный
  шелл перестаёт требовать пространства для первого рендера.

## Impact

- `internal/auth` (resolver, стратегии, middleware), `internal/http/handlers/api/v1/session/tenant`
  (упразднение переключателя), `internal/store/sessions` + миграция (удаление колонки),
  `web/static` (sidebar, api-клиент, bootstrap шелла), страница no-access.
- Машинные клиенты API, не шлющие `X-Tenant-ID`, должны получать понятный дефолт или отказ.
- HTTP-кеширование tenant-scoped ответов упрощается: ответ — функция заголовка (`Vary: X-Tenant-ID`).
