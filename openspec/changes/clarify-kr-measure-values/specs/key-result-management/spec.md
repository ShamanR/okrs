## MODIFIED Requirements

### Requirement: Значения числового KR

Система SHALL хранить у числового ключевого результата стартовое, целевое и текущее значения.

Стартовое и целевое значения — часть определения результата: они задаются при создании и
меняются редактированием результата. Текущее значение частью определения не является — это
прогресс, и оно SHALL меняться только обновлением прогресса.

При создании числового ключевого результата текущее значение MUST NOT задаваться. Операции
создания и редактирования определения результата MUST NOT менять текущее значение: переданное
в них текущее значение SHALL игнорироваться.

Пока прогресс числового ключевого результата ни разу не обновляли, система SHALL отдавать его
текущее значение равным стартовому. Правка стартового значения до первого обновления прогресса
SHALL менять и отдаваемое текущее значение. После первого обновления прогресса текущее значение
SHALL сохраняться независимо от правок стартового и целевого значений.

Отсутствие текущего значения MUST NOT протекать в данные обмена: текущее значение SHALL
оставаться числом.

#### Scenario: Числовой KR со снижением метрики

- GIVEN стартовое значение больше целевого
- WHEN ключевой результат сохраняется
- THEN он принимается: направление изменения метрики не ограничивается

#### Scenario: Правка стартового значения до первого обновления прогресса

- GIVEN создан числовой ключевой результат со стартовым значением 0 и целевым 200, прогресс ни
  разу не обновляли
- WHEN стартовое значение меняется на 100
- THEN текущее значение результата отдаётся равным 100

#### Scenario: Правка стартового значения после обновления прогресса

- GIVEN у числового ключевого результата стартовое значение 0, целевое 200, прогресс обновляли
  до 150
- WHEN стартовое значение меняется на 100
- THEN текущее значение результата остаётся равным 150

#### Scenario: Текущее значение в операции создания игнорируется

- GIVEN пользователь создаёт числовой ключевой результат и передаёт в этой же операции текущее
  значение
- WHEN результат сохраняется
- THEN переданное текущее значение не сохраняется, результат считается необновлённым, а его
  текущее значение отдаётся равным стартовому

#### Scenario: Правка определения не трогает момент обновления прогресса

- GIVEN у числового ключевого результата прогресс ни разу не обновляли
- WHEN пользователь сохраняет правку его стартового и целевого значений
- THEN результат по-прежнему считается необновлённым: момент последнего обновления прогресса
  остаётся незаданным
