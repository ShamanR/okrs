## MODIFIED Requirements

### Requirement: Состав карточки цели

Система ОБЯЗАНА показывать на карточке цели заголовок, приоритет, вес, тип работы, фокус,
драйверов цели, описание цели, прогресс с отметкой ожидаемого темпа, индикатор здоровья,
ключевые результаты и раскрываемый блок обсуждения. Описание цели ОБЯЗАНО отображаться с
сохранением разметки и в свёрнутом виде, если оно превышает ограничение по высоте.

Метаданные цели — приоритет, вес, тип работы, фокус и драйверы — ОБЯЗАНЫ размещаться в одной
строке карточки. Разносить их по нескольким строкам НЕОБХОДИМО не допускать.

Единственные раскрываемые элементы карточки — обсуждение и длинные описания. Прочие сведения
карточки ОБЯЗАНЫ быть видны без действий пользователя.

#### Scenario: Просмотр карточки

- GIVEN у цели заполнены метаданные и есть ключевые результаты
- WHEN пользователь открывает доску
- THEN на карточке отображаются метаданные, описание, прогресс и ключевые результаты, а
  раскрываемым остаётся только обсуждение

#### Scenario: Метаданные в одной строке

- GIVEN у цели заполнены приоритет, вес, тип работы, фокус и драйверы
- WHEN пользователь открывает доску
- THEN все эти метаданные отображаются в одной строке карточки

#### Scenario: Цель без описания

- GIVEN у цели не заполнено описание
- WHEN пользователь открывает доску
- THEN на карточке не отображается ни блок описания, ни элемент разворачивания

## ADDED Requirements

### Requirement: Ключевые результаты видны без раскрытия

Система ОБЯЗАНА показывать ключевые результаты цели на карточке сразу при открытии доски, без
действия пользователя. Отдельный элемент раскрытия блока ключевых результатов НЕОБХОДИМО не
показывать.

Если сумма весов ключевых результатов цели отличается от 100%, предупреждение об этом ОБЯЗАНО
отображаться на карточке и в отсутствие каких-либо действий пользователя.

#### Scenario: Цель с ключевыми результатами

- GIVEN у цели есть три ключевых результата
- WHEN пользователь открывает доску
- THEN все три ключевых результата видны на карточке, и элемента раскрытия блока нет

#### Scenario: Цель без ключевых результатов

- GIVEN у цели нет ни одного ключевого результата
- WHEN пользователь открывает доску
- THEN карточка показывает, что ключевых результатов нет, и не содержит элемента раскрытия

#### Scenario: Нарушенная сумма весов

- GIVEN сумма весов ключевых результатов цели равна 80%
- WHEN пользователь открывает доску
- THEN предупреждение о нарушенной сумме весов видно без действий пользователя

### Requirement: Свежесть цели показана одним элементом

Система ОБЯЗАНА представлять давность последнего обновления цели ровно одним элементом
карточки. Этот элемент ОБЯЗАН показывать давность обновления в любом состоянии цели и ОБЯЗАН
принимать вид предупреждения с числом дней без обновлений, когда выполнены условия требования
«Предупреждение „нет обновлений“ на карточке цели». Показывать давность обновления вторым
элементом карточки НЕОБХОДИМО не допускать.

#### Scenario: Цель обновлялась недавно

- GIVEN цель обновлялась сегодня
- WHEN пользователь открывает доску
- THEN на карточке ровно один элемент давности обновления, и он не имеет вида предупреждения

#### Scenario: Цель давно не обновлялась

- GIVEN порог «нет обновлений» равен 7 дням, команда в статусе «в работе», цель не обновлялась
  8 дней
- WHEN пользователь открывает доску
- THEN на карточке ровно один элемент давности обновления, и он имеет вид предупреждения
  «8д без обновлений»

### Requirement: Здоровье цели показано одним индикатором

Система ОБЯЗАНА представлять здоровье цели ровно одним текстовым индикатором. Цветовое
оформление процента прогресса и полосы прогресса ОБЯЗАНО следовать состоянию этого индикатора и
НЕОБХОДИМО не вводить состояний, которых у индикатора нет.

Прогноз достижения цели ОБЯЗАН отображаться в одной строке с процентом прогресса и индикатором
здоровья. Выделять прогноз в отдельную строку карточки НЕОБХОДИМО не допускать.

#### Scenario: Цель в плане

- GIVEN прогресс цели не ниже порога «в плане»
- WHEN пользователь открывает доску
- THEN на карточке ровно один текстовый индикатор здоровья, а процент и полоса прогресса
  окрашены согласно ему

#### Scenario: Прогноз в строке прогресса

- GIVEN у цели рассчитан прогноз
- WHEN пользователь открывает доску
- THEN прогноз отображается в той же строке, что процент прогресса и индикатор здоровья

### Requirement: Единый элемент редактирования цели и ключевого результата

Система ОБЯЗАНА предлагать редактирование цели и редактирование ключевого результата одним и тем
же элементом управления: иконочной кнопкой в постоянной позиции строки — у цели в строке
заголовка, у ключевого результата в строке этого результата. Подписи элемента и его расположение
ОБЯЗАНЫ совпадать для цели и для ключевого результата.

Открывать редактор цели по нажатию на её заголовок НЕОБХОДИМО не допускать: заголовок перестаёт
быть элементом управления.

Обновление прогресса ключевого результата ОБЯЗАНО предлагаться элементом того же вида, в той же
позиции строки, что и редактирование.

#### Scenario: Одинаковый вид действия у цели и у ключевого результата

- GIVEN пользователю доступно полное редактирование
- WHEN он открывает доску
- THEN редактирование цели и редактирование ключевого результата предлагаются одинаковым
  элементом в одинаковой позиции

#### Scenario: Заголовок цели не открывает редактор

- GIVEN пользователю доступно полное редактирование
- WHEN он нажимает на заголовок цели
- THEN окно редактирования цели не открывается

#### Scenario: Обновление прогресса в режиме исполнения

- GIVEN команда в статусе «в работе»
- WHEN пользователь открывает доску
- THEN обновление прогресса ключевого результата предлагается элементом того же вида и в той же
  позиции строки, что и редактирование в других статусах

#### Scenario: Доступ с клавиатуры

- GIVEN пользователю доступно полное редактирование
- WHEN он перемещает фокус клавишей Tab по карточке цели
- THEN элемент редактирования цели и элементы редактирования ключевых результатов получают фокус
  и сопровождаются названием действия
