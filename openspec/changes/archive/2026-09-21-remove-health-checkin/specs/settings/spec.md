## ADDED Requirements

### Requirement: Пороги оценки прогресса

Система ОБЯЗАНА позволять администратору пространства в разделе «Настройки» задавать пороги
оценки прогресса:

- порог «нет обновлений» в днях, больше нуля, по умолчанию 7;
- допустимое отставание от ожидаемого темпа в процентных пунктах, не меньше нуля, по умолчанию 10;
- порог «в плане» в процентах, от 1 до 100, по умолчанию 80;
- допуск по сумме весов целей, не меньше нуля, по умолчанию 0.

Значения по умолчанию ОБЯЗАНЫ действовать, пока администратор их не изменил. Недопустимые
значения НЕОБХОДИМО отклонять как ошибку валидации, не сохраняя ни одно из них.

#### Scenario: Изменение порога

- GIVEN администратор пространства меняет порог «в плане» с 80 на 70
- WHEN он сохраняет настройки и участник открывает доску команды
- THEN цель с прогрессом 75 % отображается как «в плане»

#### Scenario: Значения по умолчанию

- GIVEN администратор пространства не менял пороги
- WHEN он открывает раздел «Настройки»
- THEN блок порогов показывает 7 дней, 10 п.п., 80 % и допуск по весам 0

#### Scenario: Недопустимые значения

- GIVEN администратор задаёт неположительный порог «нет обновлений», отрицательное отставание или допуск, либо порог «в плане» вне диапазона от 1 до 100
- WHEN он сохраняет настройки
- THEN операция отклоняется как ошибка валидации, и прежние значения не меняются

#### Scenario: Доступ к порогам

- GIVEN участник без роли администратора пространства
- WHEN он пытается прочитать или изменить пороги через администрирование
- THEN доступ не предоставляется

## MODIFIED Requirements

### Requirement: Производные настройки в интерфейсе участника

Система ОБЯЗАНА отдавать авторизованному участнику значения настроек его пространства, влияющие на
отображение: порог дней без обновлений, допустимое отставание от темпа, порог «в плане», ссылку
на документацию, текст для пустой иерархии и параметры сбора обратной связи. Это ОБЯЗАНО
обеспечивать единую трактовку порогов во всех экранах интерфейса.

#### Scenario: Согласованность порогов

- GIVEN администратор изменил порог «в плане»
- WHEN участник открывает доску команды
- THEN подсветка прогресса использует новое значение без изменения кода интерфейса

#### Scenario: Признаки плоскостей администрирования приходят тем же ответом

- GIVEN участник загружает клиентскую конфигурацию
- WHEN ответ формируется
- THEN тем же ответом приходят признаки доступности администрирования пространства и администрирования инстанса; их смысл и границы применимости определяет возможность разграничения доступа
