## MODIFIED Requirements

### Requirement: Настройки уведомлений пользователя

Система ОБЯЗАНА предоставлять пользователю матрицу настроек по типам уведомлений:
включение, охват дерева команд (кроме адресных типов) и каналы доставки. Каналы
ОБЯЗАНЫ настраиваться независимо друг от друга и независимо по каждому типу: один
и тот же тип может быть включён в одном канале и выключен в другом. В матрице
ОБЯЗАНЫ отображаться все каналы, доступные пространству, независимо от того,
включены ли они у пользователя. Настройки ОБЯЗАНЫ сохраняться целиком, а не по
одной строке; сохранение матрицы считается явным выбором пользователя по каждой
её ячейке.

#### Scenario: Сохранение матрицы

- GIVEN пользователь изменил несколько строк настроек
- WHEN он сохраняет форму
- THEN сохраняется вся матрица целиком

#### Scenario: Повторное сохранение той же матрицы

- GIVEN пользователь сохраняет ту же матрицу дважды
- WHEN операция выполняется
- THEN итоговое состояние совпадает

#### Scenario: Отключение одного типа в одном канале

- GIVEN пользователю доступны канал «в приложении» и внешний канал
- WHEN он отключает тип «чек-ин ключевого результата» только во внешнем канале
- THEN этот тип продолжает приходить в ленту, но не приходит во внешний канал,
  а остальные типы во внешнем канале не меняются

#### Scenario: Неизвестный тип или охват

- GIVEN пользователь передаёт неизвестный тип уведомления или неизвестный охват
- WHEN запрос обрабатывается
- THEN операция отклоняется как ошибка валидации

#### Scenario: Неизвестный канал

- GIVEN пользователь передаёт канал, не доступный пространству
- WHEN запрос обрабатывается
- THEN операция отклоняется как ошибка валидации

### Requirement: Отсутствие настройки означает значение по умолчанию

Система ОБЯЗАНА считать отсутствие сохранённой настройки нормой и подставлять
значения по умолчанию — уведомления включены, охват «только моя команда» — как при
чтении настроек, так и при определении получателей. Значение по умолчанию для
каждого канала ОБЯЗАНО браться из настройки этого канала, заданной администратором
пространства; канал «в приложении» по умолчанию включён. Предзаполнение настроек
для всех пользователей выполняться НЕ ДОЛЖНО.

#### Scenario: Новый пользователь открывает настройки

- GIVEN пользователь ни разу не менял настройки уведомлений
- WHEN он открывает раздел настроек
- THEN он видит все типы уведомлений со значениями по умолчанию, а каналы —
  в положении, заданном администратором пространства

#### Scenario: Новый сотрудник в пространстве с настроенным каналом

- GIVEN администратор включил внешний канал по умолчанию
- WHEN в пространстве появляется новый пользователь, ни разу не открывавший настройки
- THEN уведомления доставляются ему в этот канал без каких-либо действий с его стороны

## ADDED Requirements

### Requirement: Значение канала по умолчанию применяется к тем, кто не высказался

Система ОБЯЗАНА применять текущее значение канала по умолчанию ко всем
пользователям, не сделавшим явного выбора по этому каналу и типу, — в том числе
к тем, кто ранее сохранял настройки, когда этого канала ещё не существовало.
Изменение значения по умолчанию ОБЯЗАНО немедленно отражаться на таких
пользователях.

#### Scenario: Канал подключён после того, как пользователь настроил уведомления

- GIVEN пользователь сохранял настройки до того, как канал был подключён
  пространству
- WHEN администратор подключает канал и включает его по умолчанию
- THEN пользователь начинает получать уведомления в этот канал без своих действий

#### Scenario: Администратор выключает значение по умолчанию

- GIVEN пользователь не высказывался о канале и получает уведомления по умолчанию
- WHEN администратор снимает признак «включён по умолчанию»
- THEN пользователь перестаёт получать уведомления в этот канал

### Requirement: Явный выбор пользователя переживает изменение значения по умолчанию

Система ОБЯЗАНА сохранять явный выбор пользователя по каналу и типу при любом
последующем изменении значения по умолчанию, в обе стороны. Явный выбор
переопределяться значением по умолчанию НЕ ДОЛЖЕН.

#### Scenario: Пользователь отключил канал, администратор оставил его включённым

- GIVEN пользователь явно отключил тип в канале
- WHEN администратор переключает значение по умолчанию
- THEN выбор пользователя остаётся в силе

#### Scenario: Пользователь включил канал, администратор выключил его по умолчанию

- GIVEN пользователь явно включил тип в канале, выключенном по умолчанию
- WHEN администратор оставляет значение по умолчанию выключенным
- THEN пользователь продолжает получать уведомления этого типа в этот канал

### Requirement: Запись уведомления не зависит от каналов доставки

Система ОБЯЗАНА создавать запись уведомления всякий раз, когда тип включён у
получателя и охват совпадает, независимо от того, в какие каналы это уведомление
будет доставлено. Запись уведомления ОБЯЗАНА оставаться общим источником и для
ленты, и для доставки во внешние каналы. Отключение канала «в приложении»
ОБЯЗАНО убирать уведомление из ленты и из счётчика непрочитанного, но создание
записи отменять НЕ ДОЛЖНО.

#### Scenario: Канал «в приложении» отключён, внешний канал включён

- GIVEN получатель отключил канал «в приложении» для типа и оставил включённым внешний
- WHEN для него создаётся уведомление этого типа
- THEN оно не отображается в ленте и не увеличивает счётчик непрочитанного,
  но доставляется во внешний канал

#### Scenario: Тип отключён целиком

- GIVEN получатель отключил сам тип уведомления
- WHEN происходит событие этого типа
- THEN запись уведомления не создаётся и доставка не выполняется ни в один канал
