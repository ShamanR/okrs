## Context

Мотивация — см. `proposal.md` → «Why». Нормативное поведение — см.
`specs/team-okr-board/spec.md`.

Технические рамки, которые определяют подход:

- Описания — это markdown. `renderMarkdown` (`web/static/markdown.js`) прогоняет текст через
  `marked` и `DOMPurify` и отдаёт HTML, который компонент `Markdown` вставляет через
  `dangerouslySetInnerHTML`. В итоговом HTML есть блочные элементы: `p`, `ul`/`ol`/`li`,
  `h1`–`h3`, `blockquote`, `pre`. Описание — не однострочный текст, а поддерево DOM.
- `web/static` — React через babel-in-browser, без сборки, без модулей и без JS-тестов.
  `markdown.js` загружается раньше `tracker.js` и `admin.js`, его функции доступны обоим
  приложениям как глобальные.
- Типографика описаний намеренно задаётся не в `.md-content`, а на host-элементе:
  `.goal-card__desc` (13px / line-height 1.5, `web/static/tracker.css:413`) и `.kr-desc`
  (11px / line-height 1.4, `web/static/tracker.css:317`). `markdown.css` явно запрещает
  задавать там `font-size`/`line-height`.
- Карточка цели уже использует drag-and-drop: цель перетаскивается после захвата ручки
  (`goalDraggable`), строка KR — через `draggable` на самом элементе. Клик по заголовку цели
  открывает редактор. Новый элемент управления не должен пересекаться с этими жестами.
- Изменение полностью клиентское: `UseCase.GoalTree` и слой хранения отдают описания как
  прежде. Запросов к базе данных не добавляется, кеширование не требуется, поведение в
  multi-instance Kubernetes не меняется.

## Goals / Non-Goals

**Goals:**

- Одна переиспользуемая реализация сворачивания на оба места применения (описание цели и
  описание KR), а не два локальных варианта.
- Ограничение высоты, не зависящее от структуры markdown: списки, заголовки и абзацы
  отображаются в свёрнутом виде так же, как в развёрнутом.
- Элемент разворачивания появляется только тогда, когда есть скрытый текст.

**Non-Goals:**

- Не меняется хранение, валидация и передача описаний.
- Не вводится серверный или клиентский префикс/усечение самого текста описания — в DOM
  попадает полное описание, скрыта только его визуальная часть.
- Не вводится настройка лимитов пользователем и не вводится сохранение состояния
  разворачивания.
- Не переводятся на новую механику окно обновления прогресса KR, окна редактирования,
  описание команды в шапке и раздел описаний в личных настройках.

## Decisions

### Решение 1. Ограничение по высоте контейнера, а не усечение текста

Свёрнутое состояние — это `max-height` + `overflow: hidden` на контейнере описания, поверх
низа — градиентная накладка.

Почему не альтернативы:

- **Усечение исходного markdown по числу символов или абзацев** — требует разбирать markdown
  до рендера и рвёт разметку: незакрытый список, заголовок без тела, обрезанный `pre`.
  Описания из реальных целей как раз структурные («Проблема:» + список + «Последствия»),
  поэтому этот вариант ломается на основном кейсе.
- **`-webkit-line-clamp`** работает по строкам внутри одного блочного контекста и не
  применяется к поддереву из нескольких блоков; на списках и заголовках даёт непредсказуемый
  результат.

Ограничение задаётся в `em`, кратно `line-height` host-элемента, чтобы лимит выражался в
строках текста и не зависел от `font-size`: описание цели — 4 строки, описание KR — 3 строки.
Значения выносятся в CSS-переменные на host-классах, чтобы менять их в одном месте.

Разрез по границе возможен на элементах с собственным `line-height` (заголовки, `pre`).
Это принимается: градиент маскирует границу, а полный текст доступен в один клик.

### Решение 2. Общий компонент `CollapsibleMarkdown` в `markdown.js`

Механика оформляется отдельным компонентом рядом с `Markdown` в `web/static/markdown.js`, а
`GoalCard` и `KRRow` в `web/static/tracker.js` переходят с `Markdown` на него, сохраняя
текущие классы `goal-card__desc` и `kr-desc`.

Почему не альтернативы:

- **Локальный компонент внутри `tracker.js`** — дублирование логики измерения и состояния
  между `GoalCard` и `KRRow` и невозможность переиспользовать механику позже (например, для
  описания команды в шапке), что противоречит требованию консистентности UI.
- **Встроить сворачивание прямо в `Markdown`** — сделало бы поведение по умолчанию для всех
  мест рендеринга markdown, включая окна редактирования и настройки, где оно не нужно и
  вредно. Сворачивание должно быть явным выбором места вызова.

Базовые стили сворачивания (контейнер, градиент, кнопка) живут в `markdown.css` рядом с
`.md-content`, значения лимитов — в `tracker.css` на `.goal-card__desc` и `.kr-desc`. Это
сохраняет действующее правило «типографику задаёт host-элемент».

### Решение 3. Наличие скрытого текста определяется измерением, а не эвристикой

Кнопка разворачивания рендерится только если контент реально не помещается. Признак —
сравнение `scrollHeight` элемента с его `clientHeight` в свёрнутом состоянии, измеряемое
после вставки HTML (`useLayoutEffect`) и пересчитываемое при изменении размеров через
`ResizeObserver` на контейнере.

Почему не альтернативы:

- **Всегда показывать кнопку** — нарушает требование «Короткое описание не обрезается»:
  под каждым однострочным описанием появлялся бы бессмысленный элемент управления.
- **Оценка по длине строки описания** — ненадёжна: одинаковая длина текста даёт разную
  высоту в зависимости от разметки, ширины карточки и переносов.

`ResizeObserver` нужен потому, что ширина карточки меняется при сворачивании сайдбара и
изменении окна, а высота markdown — после подгрузки шрифтов. Наблюдатель заводится один на
описание и только при непустом тексте; на доске это десятки элементов, не тысячи.

### Решение 4. Состояние разворачивания — локальный `useState`, сбрасываемый по тексту

Развёрнутость хранится в состоянии компонента описания. Ни `localStorage`
(`web/static/storage.js`), ни сервер не задействуются — это прямое следствие требования
«Состояние разворачивания описания не сохраняется». Перезагрузка страницы, смена команды и
смена периода пересоздают дерево карточек и тем самым возвращают свёрнутое состояние.

Дополнительно состояние сбрасывается при изменении самого текста описания: после
редактирования цели пользователь получает описание в том же свёрнутом виде, что и остальные.

Сброс при смене команды и периода опирается на поведение загрузки доски, а не на ключ внутри
компонента: эффект загрузки в `App` (`web/static/tracker.js`) перед запросом очищает данные
доски (`setTeamOKR(null)`), поэтому все карточки размонтируются и монтируются заново. Это
касается и общей цели, которая присутствует на досках обеих команд с тем же `key={g.id}`:
её экземпляр не переживает переключение. Если загрузку доски переведут на показ прежних данных
до прихода новых, общая цель сохранит экземпляр и развёрнутость — тогда компоненту нужен явный
ключ сброса по команде и периоду.

### Решение 5. Элемент разворачивания не конфликтует с жестами карточки

Кнопка разворачивания — отдельная `<button>` под описанием, вне `goal-card__title-row` и вне
области, по которой открывается редактор. Обработчик останавливает всплытие клика, чтобы он не
доходил до карточки или строки KR. Состояние передаётся через `aria-expanded`, чтобы элемент
читался как раскрывающий контрол.

Старт перетаскивания кнопка сама погасить не может. Строка KR перетаскивается целиком
(`draggable` на `.kr-item`), а `dragstart` диспатчится на перетаскиваемого предка и не проходит
через кнопку-потомка, поэтому ни `draggable=false`, ни обработчики на кнопке его не отменяют.
Кнопка помечается обобщённым атрибутом `data-no-drag`, а `GoalCard` на `mousedown` (в фазе
перехвата) запоминает в ref, начался ли жест на таком элементе, и в `onDragStart` отменяет
перетаскивание. Ref, а не state: значение читается синхронно, без промежуточного ре-рендера.
Карточка цели от этого не зависит — она перетаскиваема только пока зажата ручка `⋮⋮`.

### Решение 6. Печать и печатные представления не сворачиваются

В `markdown.css` добавляется `@media print`, снимающее ограничение высоты и скрывающее
градиент и кнопку: в печатной версии доски описание должно быть полным. Это не покрывается
требованиями spec как отдельное поведение доски, но необходимо, чтобы обрезание не увело
данные из бумажной копии.

### Решение 7. Скрытые ссылки исключаются из порядка перехода по Tab

`overflow: hidden` скрывает непоместившуюся часть только визуально: ссылки в ней остаются
фокусируемыми. Переход на такую ссылку по Tab прокручивает контейнер описания (у
`overflow: hidden` есть программная прокрутка), и свёрнутое описание показывает сдвинутый
фрагмент, продолжая выглядеть свёрнутым.

В свёрнутом состоянии при каждом измерении переполнения (Решение 3) ссылкам, нижняя граница
которых выходит за нижнюю границу видимой области, выставляется `tabindex="-1"`; ссылкам в
видимой части атрибут снимается. При разворачивании атрибут снимается со всех ссылок. Тот же
признак применяется к блокам `pre`: у них `overflow: auto`, и при длинных строках браузер
делает такой блок фокусируемым как прокручиваемую область. Других фокусируемых элементов
санитизированное описание содержать не может (список разрешённых тегов в `markdown.js`).
Атрибуты выставляются на узлах из `dangerouslySetInnerHTML`, которыми React не управляет,
поэтому ре-рендер их не перетирает; при смене текста HTML пересоздаётся, и эффект
перезапускается.

Почему не альтернативы:

- **Снять все ссылки описания из порядка Tab в свёрнутом виде** — видимые ссылки остались бы
  доступны мышью, но не клавиатурой.
- **`inert` на скрытой части** — описание приходит одним HTML-фрагментом, выделить из него
  «скрытую часть» как отдельный элемент нельзя без разбора разметки (см. Решение 1).
- **Разворачивать описание при фокусе на скрытой ссылке** — при проходе клавиатурой по доске
  описания раскрывались бы одно за другим; точка входа для клавиатуры — кнопка разворачивания.

## Risks / Trade-offs

- **Градиент поверх нижней строки читается как артефакт, если фон карточки нестандартный** →
  градиент строится от `transparent` к цвету фона карточки через CSS-переменную, а не
  «зашитым» белым; состояния карточки (`goal-card--stale`, `goal-card--shared`,
  `goal-card--dragging`) проверяются визуально.
- **Разрез по середине заголовка или блока кода** → лимит кратен базовому `line-height`, что
  покрывает основной случай (абзацы и списки); для прочих элементов принимается как
  компромисс, замаскированный градиентом.
- **Стоимость измерения при большом числе целей** → измерение выполняется только для непустых
  описаний, по одному `ResizeObserver` на описание, без чтения layout в цикле рендера
  списка; при отсутствии `ResizeObserver` в браузере измерение выполняется однократно после
  монтирования, и кнопка просто не пересчитывается при ресайзе.
- **Поиск по странице (Ctrl+F) находит текст в скрытой части и прокручивает к нему контейнер**
  → свёрнутое описание показывает сдвинутый фрагмент до перезагрузки или разворачивания.
  Принимается: полный текст доступен в один клик, поиск по описаниям на доске не является
  поддержанным сценарием. Автоматическое разворачивание при такой прокрутке возможно отдельным
  изменением.
- **Нет автотестов на frontend** → проверка выполняется вручную по сценариям delta spec;
  сценарии сформулированы так, чтобы каждый проверялся визуально за один шаг.

## Migration Plan

Изменение только клиентское: статические файлы `web/static`. Миграций базы данных,
изменений API и обновления demo-данных не требуется. Деплой — обычный выкат приложения,
откат — возврат предыдущей версии статики; данные при откате не затрагиваются, так как
описания не изменяются.
