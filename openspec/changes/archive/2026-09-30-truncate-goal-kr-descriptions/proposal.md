## Why

Описания целей и ключевых результатов рендерятся на доске команды целиком. Развёрнутое
описание из нескольких абзацев, списков и заголовков превращает карточку цели в полотно
текста: заголовки соседних целей уезжают за экран, прогресс и блок KR перестают быть
видимыми одновременно, а сравнить несколько целей взглядом невозможно.

Ограничение на длину описания при вводе решением не является: развёрнутое описание —
осмысленный рабочий артефакт (проблема, последствия, целевые параметры). Проблема в том,
что доска показывает его в режиме чтения документа, хотя нужна в режиме обзора.

## What Changes

- Описание цели в карточке цели на доске SHALL ограничиваться по высоте. Часть, не
  поместившаяся в ограничение, скрывается, нижняя граница видимой части затеняется
  градиентом, под описанием появляется управляющий элемент разворачивания.
- Описание ключевого результата в строке KR внутри карточки цели SHALL ограничиваться
  по высоте по той же механике, с меньшим лимитом.
- Пользователь SHALL иметь возможность развернуть описание до полного и свернуть его
  обратно, не покидая доску и не открывая редактор.
- Описание, которое целиком помещается в лимит, SHALL отображаться как сейчас — без
  градиента и без управляющего элемента.
- Состояние «развёрнуто» SHALL быть эфемерным: оно живёт в рамках текущего отображения
  карточки и не сохраняется между перезагрузками страницы.
- Обрезание применяется только к доске команды (карточка цели и строка KR внутри неё).
  Окно обновления прогресса KR, окна редактирования, описание команды в шапке, раздел
  описаний в личных настройках и экспорт не изменяются.

Breaking changes отсутствуют: изменяется только представление уже существующих данных,
контракты API и модель данных не затрагиваются.

## Capabilities

### New Capabilities

Новые capabilities не вводятся.

### Modified Capabilities

- `team-okr-board`: требование «Состав карточки цели» расширяется — описание цели
  становится явной частью состава карточки и получает ограничение по высоте с
  разворачиванием; добавляется требование к отображению описания KR в строке KR на доске.

## Impact

Затронутый код (frontend, серверная часть не меняется):

- `web/static/tracker.js` — `GoalCard` (рендер `goal.desc` через `Markdown` с классом
  `goal-card__desc`) и `KRRow` (рендер `kr.desc` через `Markdown` с классом `kr-desc`).
- `web/static/markdown.js` — общий компонент `Markdown`; сюда добавляется переиспользуемая
  обёртка сворачивания, чтобы механика не дублировалась по местам вызова.
- `web/static/markdown.css` и `web/static/tracker.css` — стили ограничения высоты,
  градиента и управляющего элемента.

Не затрагиваются: `Handler.Post` описания KR
(`internal/http/handlers/api/v1/krs/description/handler.go`), `Service.UpdateDescription`
(`internal/service/keyresult/keyresult.go`), `KRRepository.UpdateKeyResultDescription`
(`internal/store/krs/krs.go`), `UseCase.GoalTree`
(`internal/usecase/goaltree/goaltree.go`) — описания передаются и хранятся без изменений.

Обнаруженное расхождение между кодом и текущей spec: требование «Состав карточки цели» в
`openspec/specs/team-okr-board/spec.md` перечисляет заголовок, приоритет, вес, тип работы,
фокус, драйверов, прогресс и раскрываемые блоки, но не упоминает описание цели, хотя
`GoalCard` его рендерит. Этот change закрывает пробел, делая описание нормативной частью
состава карточки.

В проекте нет инфраструктуры автотестов для frontend (`web/static` — babel-in-browser без
сборки и без JS-тестов), поэтому проверка изменения выполняется вручную по сценариям из
delta spec.
