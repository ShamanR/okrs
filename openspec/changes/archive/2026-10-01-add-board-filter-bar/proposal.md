## Why

Управление показом целей на доске команды сегодня размазано по двум местам, и оба
неочевидны.

Фильтр по приоритету живёт в шапке доски, между именем лида и прогрессом узла. Шапка
читается как описание команды — название, тип, лид, прогресс, кнопка добавления цели, —
поэтому элемент управления показом целей в этом ряду не опознаётся как фильтр списка,
который начинается ниже. Других средств управления показом нет вообще: порядок целей
задаётся только перетаскиванием, а цели с нулевым весом (вес ещё не распределён или цель
выведена из расчёта) занимают место наравне с остальными.

Заметка к ключевому результату — главный носитель контекста по KR в середине периода
(блокеры, что сделано, чего ждём). Чтобы её увидеть, нужно открыть меню действий KR и
выбрать «Показать заметку» — два нажатия на каждый KR. На разборе целей с сотрудником
заметки нужны сразу по всем KR, и это превращается в десятки нажатий. Режима «показать
заметки по всей доске» нет.

## What Changes

- На доске команды между шапкой и списком целей SHALL появиться блок управления показом
  целей. Блок SHALL содержать выбор сортировки, фильтр по приоритету, признак показа
  заметок к ключевым результатам и признак скрытия целей с нулевым весом.
- Фильтр по приоритету SHALL переехать из шапки доски в этот блок. Его поведение
  (счётчик целей у уровня, недоступность уровня без целей, сброс, влияние только на показ)
  не меняется.
- Порядок целей на доске SHALL выбираться из двух вариантов: пользовательский (порядок,
  заданный перетаскиванием, — текущее поведение и значение по умолчанию) и по приоритету
  (от высшего к низшему, внутри уровня — пользовательский порядок).
- При сортировке по приоритету перетаскивание целей SHALL быть недоступно: оно меняет
  пользовательский порядок, который в этом режиме не виден, и результат перетаскивания был
  бы непредсказуем. Перетаскивание ключевых результатов внутри цели не затрагивается.
- Пользователь SHALL иметь возможность одним переключателем показать заметки ко всем
  ключевым результатам на доске. Пункт меню KR «Показать/Скрыть заметку» сохраняется и
  перекрывает общий признак для одного KR; переключение общего признака сбрасывает такие
  перекрытия.
- Пользователь SHALL иметь возможность скрыть с доски цели с нулевым весом.
- Настройки блока SHALL сохраняться между перезагрузками страницы и SHALL не сбрасываться
  при смене команды и периода.
- Когда фильтры скрыли все цели команды, доска SHALL сообщать об этом и предлагать сброс —
  сейчас при фильтре, под который не попала ни одна цель, список просто пуст и выглядит как
  команда без целей.
- Сортировка и оба фильтра SHALL сужать и переупорядочивать только показ. Прогресс
  команды, сумма весов целей, предупреждение о нарушенной сумме, охват выгрузки и расчёт
  занятого веса в окне цели SHALL считаться по всем целям периода.

Breaking changes отсутствуют: меняется только представление уже существующих данных,
контракты API и модель данных не затрагиваются.

## Capabilities

### New Capabilities

Новые capabilities не вводятся.

### Modified Capabilities

- `team-okr-board`: требование «Фильтр доски по приоритету» перестаёт привязывать фильтр к
  шапке доски и становится частью блока управления показом; требование «Меню действий цели
  и ключевого результата» дополняется пунктом показа заметки, который код уже отдаёт;
  добавляются требования к блоку управления показом, сортировке целей, скрытию целей с
  нулевым весом, показу заметок к KR с доски и сохранению этих настроек.

## Impact

Затронутый код (frontend, серверная часть не меняется):

- `web/static/tracker.js` — `PriorityFilter` (переезжает из шапки в новый блок и теряет
  `tb-`-префикс классов), новый компонент блока управления показом, `App` (состояние
  настроек вида, чтение и запись в `localStorage`, сортировка и фильтрация `allGoals`,
  передача признака показа заметок вниз, отключение перетаскивания при сортировке по
  приоритету), `GoalCard` (проброс признака в строки KR), `KRRow` (общий признак показа
  заметки и индивидуальное перекрытие).
- `web/static/storage.js` — ключ настроек вида доски в `STORAGE_KEYS`.
- `web/static/tracker.css` — стили блока, переименование `.tb-pri*`.
- `design-system/src/cards/topbar.html` — из карточки шапки убирается фильтр приоритета;
  добавляется карточка блока управления показом.
- `design-system/prototype/` — экран доски получает блок управления показом, чтобы вид
  согласовывался на прототипе.

Серверная часть не затрагивается: `/api/v1/teams/{id}/okrs` отдаёт цели и заметки KR без
изменений, порядок целей в ответе остаётся пользовательским, эндпоинты `move-up`/`move-down`
не меняются.

Обнаруженные расхождения между кодом и текущей spec, которые закрывает этот change:

1. Требование «Меню действий цели и ключевого результата» в
   `openspec/specs/team-okr-board/spec.md` перечисляет у ключевого результата
   редактирование, копирование ссылки и удаление, но не пункт показа заметки, хотя `KRRow`
   его рендерит, когда у KR есть заметка.
2. Отображение заметки к ключевому результату на доске не описано в `openspec/specs/`
   вообще — ни в `team-okr-board`, ни в `progress-tracking`, хотя строка KR её показывает.
   Этот change делает показ заметки на доске нормативным.

В проекте нет инфраструктуры автотестов для frontend (`web/static` — babel-in-browser без
сборки и без JS-тестов), поэтому проверка изменения выполняется вручную по сценариям из
delta spec.
