## MODIFIED Requirements

### Requirement: Ручной health-статус ключевого результата

Система ОБЯЗАНА хранить у ключевого результата health-статус из закрытого справочника («не
начат», «в плане», «под риском», «закрыт») со значением по умолчанию «не начат». Значение вне
справочника ОБЯЗАНО отклоняться как ошибка валидации.

Статус «закрыт» ОБЯЗАН означать, что работы по ключевому результату прекращены и его прогресс
больше не предполагается менять. Достижение результата этот статус НЕОБХОДИМО не выражать:
достигнут результат или нет ОБЯЗАНО определяться прогрессом ключевого результата, а не его
статусом. Закрыть ключевой результат ОБЯЗАНО быть возможно при любом прогрессе.

#### Scenario: Установка health-статуса

- GIVEN пользователь обновляет прогресс ключевого результата
- WHEN он одновременно передаёт допустимый health-статус
- THEN health-статус сохраняется

#### Scenario: Недопустимый health-статус

- GIVEN пользователь передаёт health-статус вне справочника
- WHEN запрос обрабатывается
- THEN операция отклоняется как ошибка валидации

#### Scenario: Закрытие без достижения результата

- **GIVEN** прогресс ключевого результата равен 40
- **WHEN** пользователь ставит ему статус «закрыт»
- **THEN** статус сохраняется, прогресс остаётся равным 40
- **AND** результат не считается достигнутым

## ADDED Requirements

### Requirement: Однократный автоматический переход в «закрыт»

Система ОБЯЗАНА при переходе прогресса ключевого результата снизу вверх через 100 процентов
однократно выставлять health-статус «закрыт», если он ещё не «закрыт». Повторное сохранение на
100 процентах и падение прогресса ниже 100 процентов health-статус НЕОБХОДИМО не менять. Явно
переданный статус ОБЯЗАН иметь приоритет над автоматическим.

#### Scenario: Достижение 100 процентов

- GIVEN прогресс ключевого результата меньше 100 и health-статус не «закрыт»
- WHEN прогресс становится равен 100
- THEN health-статус автоматически становится «закрыт»

#### Scenario: Пользователь снял статус после автоперехода

- GIVEN health-статус был автоматически выставлен «закрыт», а затем изменён вручную
- WHEN прогресс сохраняется снова на 100 процентах
- THEN автоматический переход не повторяется и ручное значение сохраняется

#### Scenario: Падение прогресса ниже 100

- GIVEN health-статус «закрыт», прогресс равен 100
- WHEN прогресс уменьшается
- THEN health-статус остаётся «закрыт», а результат перестаёт считаться достигнутым

#### Scenario: Явный статус вместе с достижением 100 процентов

- GIVEN прогресс достигает 100 процентов
- WHEN в том же обновлении явно передан другой health-статус
- THEN сохраняется явно переданный статус

## REMOVED Requirements

### Requirement: Однократный автоматический переход в «выполнен»

**Reason**: Четвёртый health-статус получает нормативное имя «закрыт»: он ставится вручную и
утверждает прекращение работ, а не факт достижения результата. Требование заменено на
«Однократный автоматический переход в «закрыт»».

**Migration**: Механика не меняется — тот же однократный автоматический переход при прохождении
прогресса через 100 процентов, тот же приоритет явно переданного статуса. Меняется только имя
значения в спецификации; справочник, хранимые данные и контракт API остаются прежними.
