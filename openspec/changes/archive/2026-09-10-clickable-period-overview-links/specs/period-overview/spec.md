## ADDED Requirements

### Requirement: Переход к сущности из состава обзора

Система ОБЯЗАНА сопровождать каждую строку раскрытого состава обзора переходом к затронутой
сущности: строку команды — переходом на доску целей этой команды в периоде обзора, строку
цели — переходом к этой цели, строку ключевого результата — переходом к этому ключевому
результату внутри его цели.

Переход ОБЯЗАН открываться отдельно от обзора, не заменяя его: после перехода обзор ОБЯЗАН
оставаться открытым в исходном окне.

Требование ОБЯЗАНО действовать одинаково во всех местах отображения обзора: и на отдельной
странице обзора, и в модальном окне обзора в администрировании.

#### Scenario: Переход к команде из плитки статуса

- **GIVEN** пользователь раскрыл состав плитки статуса и видит список команд
- **WHEN** он выбирает переход по строке команды
- **THEN** открывается доска целей этой команды в периоде обзора
- **AND** обзор остаётся открыт в исходном окне

#### Scenario: Переход к цели из детализации баланса

- **GIVEN** пользователь раскрыл состав корзины баланса и видит список целей
- **WHEN** он выбирает переход по строке цели
- **THEN** открывается доска целей команды этой цели в периоде обзора
- **AND** указанная цель раскрыта

#### Scenario: Переход к ключевому результату из детализации health-статусов

- **GIVEN** пользователь раскрыл корзину баланса health-статусов и видит список ключевых
  результатов
- **WHEN** он выбирает переход по строке ключевого результата
- **THEN** открывается доска целей команды этого ключевого результата в периоде обзора
- **AND** раскрыта его цель и выделен сам ключевой результат

#### Scenario: Обзор из администрирования

- **GIVEN** администратор пространства открыл обзор периода в модальном окне
  администрирования
- **WHEN** он выбирает переход по строке состава
- **THEN** переход ведёт к той же сущности, что и со страницы обзора, а модальное окно
  остаётся открытым

### Requirement: Команда перехода определена однозначно и лежит в охвате

Общая цель присутствует в нескольких командах, поэтому система ОБЯЗАНА связывать цель и её
ключевые результаты в обзоре ровно с одной командой и ОБЯЗАНА выбирать её детерминированно:
повторный запрос обзора при неизменных данных ОБЯЗАН давать ту же команду.

Выбранная команда ОБЯЗАНА принадлежать текущему охвату обзора. Если команда-владелец цели в
охват не входит, система ОБЯЗАНА выбирать команду из числа входящих в охват команд этой цели.

#### Scenario: Общая цель в нескольких командах охвата

- **GIVEN** цель расшарена в несколько команд охвата
- **WHEN** пользователь дважды открывает обзор периода при неизменных данных
- **THEN** цель оба раза показана с одной и той же командой и переход ведёт в неё же

#### Scenario: Владелец общей цели вне охвата

- **GIVEN** цель принадлежит команде вне охвата и расшарена в команду охвата
- **WHEN** пользователь смотрит детализацию с этой целью
- **THEN** цель связана с командой из охвата, и переход ведёт на её доску

## MODIFIED Requirements

### Requirement: Список ключевых результатов для детализации

Система ОБЯЗАНА отдавать вместе с обзором периода список ключевых результатов охвата с их
заголовком, названием цели, названием команды, health-статусом и прогрессом, чтобы по клику на
корзину баланса health-статусов раскрывался её состав.

Каждый ключевой результат в списке ОБЯЗАН сопровождаться идентификаторами своей цели и своей
команды, достаточными для перехода к нему.

#### Scenario: Детализация корзины

- GIVEN пользователь видит распределение по health-статусам
- WHEN он выбирает корзину «под риском»
- THEN он видит ключевые результаты этой корзины с их целью, командой и прогрессом

#### Scenario: Данные для перехода

- **GIVEN** обзор периода содержит ключевые результаты
- **WHEN** клиент получает список ключевых результатов
- **THEN** у каждого из них известны цель и команда, к которым ведёт переход
