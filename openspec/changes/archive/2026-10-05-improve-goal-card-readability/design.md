# Design

## Контекст

Карточка цели собирается React-компонентами без шаблонного слоя:

- `GoalCard` (`web/static/tracker.js`) — шапка `.gc2__head` как flex-строка, полоса участников
  `.gc-share-strip`, секция ключевых результатов;
- `KRRow` (`web/static/tracker.js`) — строка `.kr-row__main` как CSS-сетка;
- вся геометрия — в `web/static/tracker.css`, в блоках «КОМПАКТНАЯ ПЛОТНОСТЬ ЦЕЛЕЙ» и
  «Компактная раскладка карточки цели (gc2)», которые перекрывают базовые правила выше.

Отправная точка (эффективные значения, а не базовые):

| элемент | селектор | сейчас |
| --- | --- | --- |
| заголовок цели | `.gc2 .goal-card__title` | 15.5px / 1.35, `nowrap` + многоточие |
| промежуток между карточками | `.goal-card` | `margin-bottom: 8px` |
| полоса прогресса цели | `.gc2__head .gc2__bar` | `flex: 0 0 120px` |
| шапка (растяжимая часть) | `.gc2__title-wrap` | `flex: 1 1 200px; min-width: 120px` |
| строка KR | `.kr-row__main` | сетка `auto auto minmax(180px,1fr) minmax(96px,160px) minmax(130px,190px) auto`, `column-gap: 14px` |
| узкая строка KR | `@container (max-width: 720px) .kr-measure` | flex, `gap: 12px` |
| драйверы | `.gc2__owner` | `flex-shrink: 0`, всегда аватар + имя |
| команды-участники | `.gc-share-strip__team` | `<span>` |

Шапка — flex, и `.gc2__title-wrap` единственный растяжимый элемент в ней: всё, что отнимается
у полосы прогресса, достаётся заголовку автоматически. В строке KR то же делает трек `1fr`
(`.kr-info`).

## Решения

### 1. Заголовок цели — 17px

`.goal-card__title`: 15px → 17px, `.gc2 .goal-card__title`: 15.5px/1.35 → 17px/1.3.

17px взяты вместо буквальных 18pt (= 24px) сознательно. При межстрочном 1.3 это даёт
17 × 1.3 ≈ 22px — ровно высоту, которую строка шапки уже занимает (`.gc2__weight` имеет
`height: 22px`), поэтому шапка не становится выше и не начинает ломаться на две строки, что
прямо запрещено требованием «Шапка в одной строке». 24px подняли бы строку примерно на 10px,
потребовали бы подгонки чипа веса и процента и съели бы по ширине то самое место, которое
решения 3–5 освобождают под заголовки.

Оба селектора правятся вместе, чтобы базовое и gc2-значение не расходились: `.goal-card__title`
вне `.gc2` не встречается в приложении, но встречается в карточке типографики дизайн-системы,
и расхождение сделало бы карточку неправдивой.

### 2. Промежуток между карточками — 14px

`.goal-card { margin-bottom: 8px }` → `14px` в блоке «КОМПАКТНАЯ ПЛОТНОСТЬ ЦЕЛЕЙ».

Отдельного разделителя не вводим: у карточки есть рамка и тень, промежутка достаточно.

### 3. Полоса прогресса цели — 84px

`.gc2__head .gc2__bar { flex: 0 0 120px }` → `flex: 0 0 84px`.

Освободившиеся 36px уходят в `.gc2__title-wrap` (единственный `flex-grow` в шапке), то есть
заголовку и лейблам. Процент прогресса (`.goal-card__progress-pct`, `min-width: 42px`,
`tabular-nums`) не трогаем — он и есть точное значение; полоса остаётся индикатором темпа, и
на 84px отметка прогноза (`.progress-bar__forecast`, позиционируется в процентах) по-прежнему
различима.

### 4. Колонка прогресса KR — 112–136px

Пятый трек сетки `.kr-row__main`: `minmax(130px,190px)` → `minmax(112px,136px)`.

Внутри колонки геометрия фиксированная: `.kr-progress-col__body--row` — flex с `gap: 8px`,
процент имеет `min-width: 38px`. Значит на саму полосу остаётся 112 − 38 − 8 = 66px в минимуме
и 90px в максимуме вместо прежних 84–146px. Освободившееся уходит в трек `1fr`, то есть в
`.kr-info` — название ключевого результата и его описание.

### 5. Зазор «целевое значение ↔ полоса прогресса» — 8px

Сетке нельзя задать зазор отдельной колонки: `column-gap` действует на все. Поэтому общий
`column-gap: 14px` остаётся (между весом, названием, действиями он уместен), а колонка
прогресса подтягивается влево:

```css
.kr-progress-col { margin-left: -6px; }
```

Отрицательный отступ съедает часть пустого зазора, перекрывать ему нечего. Эффективный зазор
становится 8px, и это ещё ~6px названию.

В узкой раскладке (`@container (max-width: 720px)`) измерение перестаёт быть сеткой и
становится flex-строкой `.kr-measure` с `gap: 12px`: там зазор правится напрямую (`gap: 8px`),
а отрицательный отступ сбрасывается (`margin-left: 0`), иначе зазор сократился бы дважды.

### 6. Имена драйверов показываются, пока вмещаются

Правило не «больше двух драйверов», а «пока имена не обрезают заголовок». Порог по количеству
был бы неверен в обе стороны: один драйвер при длинном заголовке и узком окне уже вытесняет
текст, а три коротких имени при коротком заголовке на широком мониторе помещаются свободно.

Переключение — тот же модификатор, что и при пороге:

```css
.gc2__owner--compact .uinfo__name { display: none; }
```

Имя не теряется: `UserInfo` уже показывает при наведении карточку пользователя с именем,
почтой и командой (`.uinfo__popup`), и она работает для аватара без подписи так же. Поэтому
ни новой подсказки, ни счётчика «+N» не вводим — список остаётся полным, меняется только форма.

#### Почему измеряем, а не считаем

Посчитать «влезут ли имена» из геометрии нельзя: шапка — flex-строка, в которой сжимаются
и `.gc2__title-wrap` (`flex: 1 1 200px`), и `.gc2__labels` (`flex: 0 1 auto; overflow: hidden`),
а `.gc2__owner` имеет `flex-shrink: 0`. Сколько именно отнимут имена у заголовка, а сколько у
лейблов, зависит от их содержимого. Поэтому критерий берём прямо из постановки и прямо
измеряем его: обрезан ли заголовок (`scrollWidth > clientWidth`) — тот же признак, который уже
считает `useOverflowTitle` (решение 8). Чтобы не мерить дважды, хук переименован в
`useClipped` и возвращает признак обрезки; подсказка и решение о драйверах строятся на нём.

#### Почему нужна отметка «на какой ширине не влезло»

Решение меняет раскладку, которую само же измеряет: убрали имена — заголовок перестал
обрезаться — значит «место есть» — возвращаем имена — заголовок снова обрезан. Это замкнутый
цикл. Разрывается он памятью о ширине шапки, на которой имена не влезли:

```js
function useOwnersFit(titleClipped, resetKey) {
  const headRef = useRef(null);
  const [compact, setCompact] = useState(false);
  // Ширина шапки, на которой имена не влезли. Пока шапка не стала шире, пробовать снова
  // незачем: получили бы тот же обрезанный заголовок и лишний цикл раскладки.
  const brokeAt = useRef(Infinity);
  …
}
```

- имена показаны и заголовок обрезан → убираем имена, запоминаем ширину шапки;
- имена убраны и шапка стала шире запомненного → пробуем снова с именами;
- иначе ничего не делаем.

Состояние сходится: после возврата имён заголовок либо помещается (остаёмся с именами), либо
обрезается — и тогда отметка поднимается до новой, большей ширины. На каждое расширение окна
приходится максимум одна лишняя попытка, на сужение — ни одной. Без отметки каждое событие
изменения размера давало бы два лишних рендера на каждую карточку доски.

Отметка верна только для того содержимого шапки, на котором её получили, поэтому в `resetKey`
входит всё, что делит с заголовком место по горизонтали: сам заголовок, **имена** драйверов,
лейблы типа и фокуса, вес, приоритет и количество связей вверх и вниз.

Одного количества драйверов тут недостаточно, и это не теоретическая придирка: пока имена
скрыты, замена драйвера на другого с тем же количеством не меняет ни ширину их блока (имена
убраны через `display: none`), ни ширину заголовка, ни ширину шапки. Ни один наблюдатель не
срабатывает, ключ не меняется — и короткое имя осталось бы скрытым до постороннего изменения
размера окна, превысившего полосу повторной попытки. По той же причине в ключе лейблы, связи,
вес и приоритет: их правка меняет доступную заголовку ширину, не меняя ширины шапки.

Прогресса в ключе нет намеренно: у процента `min-width: 42px` и табличные цифры, его ширина от
значения не зависит, а обновляется он часто — сброс на каждом обновлении прогресса был бы
впустую.

Наблюдаем `.gc2__head`, а не окно: его ширина меняется и при изменении размера окна, и при
сворачивании боковой панели, и наше собственное переключение её не меняет — меняется состав
её детей, — поэтому наблюдатель не реагирует на собственную правку.

Измерение и переключение идут в `useLayoutEffect`, то есть до отрисовки: промежуточное
состояние «имена показаны и заголовок обрезан» на экран не попадает.

В прототипе React-состояния нет, поэтому то же правило выражено одним проходом по DOM после
отрисовки и по изменению размера окна: снять модификатор со всех шапок, измерить, вернуть
там, где заголовок обрезан. Императивный проход цикла не образует, и отметка ему не нужна.

Отсюда расхождение, о котором нужно помнить при согласовании вида: у прототипа полосы нет, и
имена возвращаются сразу, как только помещаются, а в приложении — когда шапка стала шире на
`OWNERS_REFIT_PX` сверх точки, где они не влезли. Установившееся состояние на любой фиксированной
ширине у них одинаковое, различается только момент возврата при протягивании границы окна.

### 7. Название команды-участника — переход

В `.gc-share-strip` название каждой команды, кроме текущей, рендерится ссылкой; адрес строится
существующим `buildTargetURL` из `web/static/ui.js`:

```js
const href = buildTargetURL({ team_id: t.id, period_id: periodId });
```

Период берётся из пропа `periodId` карточки: общая цель принадлежит одному периоду, и все
команды-участники видят её в нём же.

Решения внутри:

- **`<a href>`, а не кнопка с `location.assign`.** `GoalLinksPopover` переходит через
  `location.assign`, потому что живёт во всплывающем списке; здесь элемент статичен, и ссылка
  даёт бесплатно открытие в новой вкладке средним щелчком и контекстное меню браузера.
- **Та же вкладка, без `target="_blank"`.** В обзоре периода переход открывается в новой
  вкладке, чтобы не потерять сам обзор. Здесь источник и цель — одна и та же доска целей, и
  накапливать вкладки незачем.
- **Текущая команда остаётся `<span>`.** Ссылка на уже открытую доску ничего не даёт.
- **Доступность не проверяется на клиенте.** Состав участников по требованию полон, а правило
  для ссылки на недоступную команду у доски уже зафиксировано — дублировать его в карточке
  значило бы прятать команду из состава.

Оформление: ссылка наследует вид пилюли, `text-decoration: none`, при наведении усиливается
рамка (и фон у пилюли владельца) — то есть по виду она не отличается от текущей пилюли, пока
на неё не наведёшься.

### 8. Полный текст обрезанного заголовка

Заголовок цели (`.goal-card__title`) и название KR (`.kr-name`) обрезаются через
`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`. Решение — атрибут `title` на
самом обрезанном элементе, выставляемый только когда обрезка фактически есть.

Почему именно так:

- **Атрибут `title` на внутреннем элементе перекрывает `title` предка.** Строка заголовка
  (`.goal-card__title-row`, `.kr-name-row`) в режиме редактирования несёт
  `title="Редактировать цель"` / `"Редактировать KR"`. Подсказка внутреннего элемента
  вытесняет её на время наведения именно на текст — ровно то поведение, которое нужно: пока
  заголовок влезает, подсказки у него нет и видна подсказка действия.
- **Обрезку нельзя угадать, её нужно измерить.** Один и тот же текст обрезается или нет в
  зависимости от количества лейблов, драйверов, связей и ширины окна. Это тот же случай, что у
  `CollapsibleMarkdown` (`web/static/markdown.js`), и мерить будем так же: `useLayoutEffect` +
  `ResizeObserver`, сравнение `scrollWidth` с `clientWidth` с запасом 1px на субпиксельное
  округление.

Общий хук в `web/static/tracker.js`, рядом с местами применения:

```js
function useClipped(text) {
  const ref = useRef(null);
  const [clipped, setClipped] = useState(false);
  React.useLayoutEffect(() => {
    const el = ref.current;
    if (!el) return undefined;
    const measure = () => setClipped(el.scrollWidth - el.clientWidth > 1);
    measure();
    if (typeof ResizeObserver === 'undefined') return undefined;
    const ro = new ResizeObserver(measure);
    ro.observe(el);
    return () => ro.disconnect();
  }, [text]);
  return [ref, clipped];
}
```

Возвращает ссылку и признак обрезки. Подсказка строится на нём (`title={clipped ? text :
undefined}` — при `undefined` React атрибут не выставляет, и видна подсказка предка), и на нём
же строится решение о драйверах (решение 6), поэтому заголовок измеряется один раз.
`ResizeObserver` на элементе с `nowrap` срабатывает при изменении его `clientWidth`, то есть
на изменение размера окна и сворачивание боковой панели; без `ResizeObserver` (старый браузер)
остаётся измерение при монтировании.

Пропускать измерение в нередактируемом режиме не нужно: там у предка подсказки нет, и
конфликта тоже.

## Интерфейс

Новых компонентов дизайн-системы не появляется — меняются существующие:

| компонент | карточка | что меняется |
| --- | --- | --- |
| карточка цели | `design-system/src/cards/goal-card.html` | размер заголовка, ширина полосы прогресса, компактные драйверы (нужен образец с тремя), ссылка в полосе участников |
| строка KR | `design-system/src/cards/kr-row.html` | ширина колонки прогресса, зазор до целевого значения |
| типографика | `design-system/src/cards/foundations-typography.html` | подпись образца `.goal-card__title` — 17/700 вместо 15/700 |

Полоса участников (`.gc-share-strip`) и всплывающая карточка пользователя (`.uinfo__popup`)
переиспользуются как есть; `.uinfo__name` не удаляется, а скрывается модификатором — вне
компактного режима он нужен.

Вид согласуется на прототипе (`design-system/prototype/`, экран трекера, карточка цели) **до**
реализации в приложении: прототип собран на реальном `web/static/*.css`, поэтому расхождения
со стилями приложения не даёт. Скриншоты в change не добавляем.

## Что осознанно не делаем

- **Не переносим заголовок на вторую строку.** Это прямо запрещено требованием «Шапка в одной
  строке», и именно многострочная шапка была тем, от чего уходил редизайн доски.
- **Не вводим «+N» и не сворачиваем список драйверов.** Карточка не должна терять сведения;
  скрывается подпись, а не человек.
- **Не вводим порог по количеству драйверов и не прячем имена по ширине окна через
  `@container`.** Порог и медиазапрос не знают длины заголовка, поэтому ошибались бы в обе
  стороны: прятали бы имена там, где места вдоволь, и оставляли бы их там, где заголовок уже
  обрезан. Критерий у постановки содержательный, значит и проверять его нужно измерением.
- **Не прячем имена плавно (многоточием, сужением).** Имя, сжатое до «Анн…», занимает место и
  ничего не сообщает; аватар с полным именем по наведению сообщает больше и места не занимает.
- **Не делаем полосу прогресса резиновой.** Фиксированная ширина держит столбец процентов
  выровненным по всем целям; резиновая полоса ломала бы это ради нескольких пикселей.
- **Не показываем подсказку с текстом безусловно.** Дубль видимого текста — шум, и он отнимает
  подсказку у действия «Редактировать».
- **Не трогаем расчёты прогресса, API и схему данных.** Изменение целиком в представлении.

## Риски и проверка

| риск | проверка |
| --- | --- |
| шапка ломается на две строки на узкой доске | проход по ширинам окна, в том числе с развёрнутой боковой панелью и длинным заголовком |
| отрицательный отступ колонки прогресса ломает узкую раскладку | проверка в `@container (max-width: 720px)`: зазор 8px, наложения нет |
| полоса прогресса на 66px перестаёт читаться | проверка KR с прогрессом 0 / 1 / 50 / 100% и с отметкой прогноза |
| обрезка измеряется до применения шрифтов и выходит неверной | `ResizeObserver` переизмеряет после догрузки шрифтов — тот же механизм, что в `CollapsibleMarkdown` |
| имена драйверов мигают при протягивании границы окна | переключение в `useLayoutEffect` (до отрисовки) и отметка «не влезло на этой ширине»: при сужении попыток нет, при расширении максимум одна на шаг |
| отметка устаревает после правки заголовка или состава драйверов | сброс по `resetKey`; проверка: переименовать цель на узком окне и убедиться, что имена возвращаются, когда заголовок стал коротким |
| ссылка ведёт в недоступную команду | ручная проверка: доска отвечает уже зафиксированным поведением для недоступной команды |

Автоматических тестов фронтенда в проекте нет (ни одного `*.test.js`, нет `package.json`), а
изменение целиком презентационное, поэтому покрыть его тестами нечем. Проверка: разбор
изменённых JS вендорным `web/static/vendor/babel.min.js` (JSX) и ручной проход по сценариям
delta specs на реальной доске.
