# Period Overview Specification

## Purpose

Обзор периода отвечает на вопрос «как идут дела» по срезу команд: сводка по статусам, качество
оформления целей, балансы целей по типам, список целей для детализации и график динамики
прогресса, накапливаемый суточными снимками.

## Requirements

### Requirement: Охват обзора

Система SHALL предоставлять обзор периода в двух охватах: «мои команды» — команды, где
пользователь назначен руководителем, вместе со всеми вложенными потомками; и «вся организация» —
все команды пространства. Охват «мои команды» SHALL быть доступен любому участнику и
использоваться по умолчанию. Охват «вся организация» SHALL быть доступен только администратору
пространства.

#### Scenario: Участник смотрит свои команды

- GIVEN участник назначен руководителем команды с потомками
- WHEN он открывает обзор периода без указания охвата
- THEN обзор строится по его командам и их потомкам

#### Scenario: Участник без своих команд

- GIVEN участник не назначен руководителем ни одной команды
- WHEN он открывает обзор периода в охвате «мои команды»
- THEN обзор пуст

#### Scenario: Охват «вся организация» без прав

- GIVEN участник без роли администратора пространства
- WHEN он запрашивает обзор в охвате «вся организация»
- THEN доступ не предоставляется

#### Scenario: Кнопка охвата в интерфейсе

- GIVEN участник без роли администратора пространства
- WHEN он открывает обзор периода
- THEN переключатель «Вся организация» ему не показывается

### Requirement: Охват применяется ко всем секциям одинаково

Система SHALL применять выбранный охват ко всем секциям обзора: сводке статусов, качеству
оформления, балансам, списку целей и графику прогресса.

#### Scenario: Смена охвата

- GIVEN администратор пространства открыл обзор в охвате «мои команды»
- WHEN он переключается на охват «вся организация»
- THEN пересчитываются все секции, а не только сводка

### Requirement: Сводка по статусам и составу

Система SHALL показывать в сводке число команд охвата, число команд с целями и распределение
команд по статусам в периоде.

#### Scenario: Сводка охвата

- GIVEN в охвате есть команды в разных статусах
- WHEN пользователь открывает обзор
- THEN сводка показывает общее число команд, число команд с целями и разбивку по статусам

### Requirement: Контроль корректности весов

Система SHALL выявлять команды, у которых сумма весов целей в периоде выходит за допустимый
предел, и SHALL показывать их число в сводке и признак ошибки у каждой команды. Допуск SHALL
браться из настроек пространства.

#### Scenario: Команда с некорректной суммой весов

- GIVEN у команды сумма весов целей выходит за допуск
- WHEN пользователь открывает обзор
- THEN команда помечена признаком ошибки весов и учтена в счётчике таких команд

### Requirement: Средний прогресс исключает формирующиеся команды

Система SHALL исключать из расчёта среднего прогресса и из графика динамики команды без целей и
команды в статусе «черновик». Балансы и список целей при этом SHALL учитывать все цели охвата.

#### Scenario: Команда в статусе «черновик»

- GIVEN в охвате есть команда в статусе «черновик» с целями
- WHEN вычисляется средний прогресс охвата
- THEN эта команда в расчёт не входит, а её цели попадают в балансы и список целей

### Requirement: Балансы целей

Система SHALL показывать распределение целей охвата по типу работы, фокусу и приоритету. Каждая
корзина SHALL содержать все фиксированные категории, включая нулевые, с указанием доли от числа
целей охвата.

#### Scenario: Категория без целей

- GIVEN в охвате нет ни одной цели с определённым фокусом
- WHEN пользователь смотрит баланс по фокусам
- THEN категория присутствует в списке с нулевым значением

#### Scenario: Детализация по клику

- GIVEN пользователь видит распределение целей по приоритетам
- WHEN он выбирает конкретный приоритет
- THEN он видит цели охвата с этим приоритетом

### Requirement: График динамики прогресса

Система SHALL показывать ряд среднего прогресса охвата по датам, построенный из суточных снимков,
и SHALL добавлять к историческим точкам «живую» точку на текущий день из актуального состояния.

#### Scenario: Просмотр динамики

- GIVEN по периоду накоплены снимки за несколько дней
- WHEN пользователь открывает обзор
- THEN он видит ряд точек по датам и текущее значение на сегодня

### Requirement: Суточный снимок прогресса

Система SHALL фиксировать снимок взвешенного прогресса команды в периоде не чаще одного раза в
день. Повторная запись за тот же день SHALL быть идемпотентной и обновлять значение.

#### Scenario: Повторный снимок за день

- GIVEN снимок команды за сегодняшнюю дату уже записан
- WHEN снимок фиксируется повторно
- THEN новая точка не добавляется, а существующее значение обновляется

### Requirement: Область снятия снимков

Система SHALL фиксировать снимки только для периодов, активных по датам. Закрытые и архивные
периоды, команды без целей и мягко удалённые команды SHALL пропускаться.

#### Scenario: Закрытый период

- GIVEN период закрыт по датам
- WHEN выполняется фоновая фиксация снимков
- THEN снимки по этому периоду не создаются

#### Scenario: Команда без целей

- GIVEN у команды в активном периоде нет целей
- WHEN выполняется фоновая фиксация снимков
- THEN снимок по этой команде не создаётся

### Requirement: Настраиваемая частота снимков

Система SHALL брать интервал фиксации точек прогресса из настройки пространства со значением по
умолчанию «ежедневно». Новая точка SHALL записываться, когда с последнего снимка периода прошло не
меньше заданного интервала.

#### Scenario: Интервал в три дня

- GIVEN интервал фиксации задан в три дня, последний снимок сделан вчера
- WHEN выполняется фоновая фиксация
- THEN новая точка не записывается

### Requirement: Значение интервала снимков приводится к допустимому

Система SHALL приводить сохраняемый интервал фиксации снимков меньше одного дня к одному дню, а не
отклонять его как ошибку валидации. Опущенное в запросе значение SHALL сохранять ранее заданный
интервал.

#### Scenario: Значение меньше допустимого

- GIVEN администратор пространства сохраняет интервал, меньший одного дня
- WHEN настройки сохраняются
- THEN сохраняется интервал в один день, ошибка не возвращается

#### Scenario: Сохранение прочих общих настроек

- GIVEN интервал ранее задан в три дня
- WHEN администратор сохраняет общие настройки, не передавая интервал
- THEN ранее заданный интервал сохраняется неизменным

### Requirement: Баланс ключевых результатов по health-статусам

Система SHALL показывать в обзоре периода распределение ключевых результатов охвата по их
health-статусам. Корзины SHALL присутствовать всегда и в фиксированном порядке: «не начат», «в
плане», «под риском», «выполнен», включая корзины с нулевым значением.

#### Scenario: Просмотр баланса по health-статусам

- GIVEN в охвате есть ключевые результаты с разными health-статусами
- WHEN пользователь открывает обзор периода
- THEN он видит распределение по четырём health-статусам с количеством и долей каждого

#### Scenario: Health-статус без ключевых результатов

- GIVEN в охвате нет ни одного ключевого результата со статусом «под риском»
- WHEN пользователь смотрит баланс
- THEN корзина «под риском» присутствует с нулевым значением

### Requirement: Список ключевых результатов для детализации

Система SHALL отдавать вместе с обзором периода список ключевых результатов охвата с их
заголовком, названием цели, названием команды, health-статусом и прогрессом, чтобы по клику на
корзину баланса health-статусов раскрывался её состав.

#### Scenario: Детализация корзины

- GIVEN пользователь видит распределение по health-статусам
- WHEN он выбирает корзину «под риском»
- THEN он видит ключевые результаты этой корзины с их целью, командой и прогрессом

### Requirement: Однократная фиксация снимков в многоинстансной среде

Система SHALL гарантировать, что при работе нескольких экземпляров приложения снимок за цикл
делает только один из них.

#### Scenario: Одновременный проход двух экземпляров

- GIVEN приложение развёрнуто в нескольких экземплярах
- WHEN оба одновременно начинают цикл фиксации снимков
- THEN снимки создаются один раз, дубликаты точек не появляются

### Requirement: Массовые действия из обзора

Система SHALL позволять выполнять из обзора массовый перевод команд охвата в статусы «в работе»
и «закрыт». Область действия SHALL совпадать с разрешённым охватом вызывающего, и проверки
доступа SHALL совпадать с проверками обзора.

#### Scenario: Руководитель активирует свои команды

- GIVEN руководитель открыл обзор в охвате «мои команды»
- WHEN он выполняет массовую активацию
- THEN затрагиваются только его команды и их потомки

#### Scenario: Управление периодом в охвате организации

- GIVEN участник без роли администратора пространства
- WHEN он пытается выполнить массовую операцию в охвате «вся организация»
- THEN операция отклоняется
