# User Directory Specification

## Purpose

Справочник пользователей отвечает на вопрос «кто эти люди»: находит человека для назначения
драйвером цели или руководителем команды и разворачивает уже известные ссылки на пользователей
(авторы замечаний и заметок, руководители команд) в имя, аватар и контакт. Видимость людей в
поиске ограничена зоной иерархии, доступной ищущему.

## Requirements

### Requirement: Два режима справочника

Система SHALL поддерживать два режима: загрузку пользователей по списку известных
идентификаторов и поиск по строке. Хотя бы один из режимов MUST быть запрошен явно; запрос без
параметров SHALL отклоняться как ошибка валидации.

#### Scenario: Запрос без параметров

- GIVEN авторизованный пользователь
- WHEN он запрашивает справочник, не указав ни списка идентификаторов, ни строки поиска
- THEN запрос отклоняется как ошибка валидации

#### Scenario: Оба параметра сразу

- GIVEN запрос содержит и список идентификаторов, и строку поиска
- WHEN он обрабатывается
- THEN применяется режим загрузки по идентификаторам

### Requirement: Загрузка по известным идентификаторам

Система SHALL возвращать пользователей по списку их публичных идентификаторов без ограничения
областью видимости, поскольку режим служит разворачиванию уже показанных на странице ссылок.
Список SHALL ограничиваться сотней идентификаторов за запрос; лишние SHALL отбрасываться.

#### Scenario: Разворачивание авторов замечаний

- GIVEN на доске отображаются замечания нескольких авторов
- WHEN клиент запрашивает их по идентификаторам
- THEN возвращаются имя, аватар, провайдер и контакт каждого, независимо от области видимости запрашивающего

#### Scenario: Список длиннее сотни

- GIVEN запрос содержит больше ста идентификаторов
- WHEN он обрабатывается
- THEN обрабатываются первые сто, остальные отбрасываются без ошибки

#### Scenario: Неизвестный идентификатор

- GIVEN в списке есть идентификатор несуществующего пользователя
- WHEN запрос обрабатывается
- THEN он молча пропускается, остальные пользователи возвращаются

### Requirement: Системные пользователи не входят в справочник

Система MUST NOT возвращать в справочнике системных пользователей.

#### Scenario: Запрос системного пользователя по идентификатору

- GIVEN запрашивается идентификатор системного пользователя
- WHEN запрос обрабатывается
- THEN этот пользователь в ответе отсутствует

### Requirement: Поиск по имени и контакту

Система SHALL искать пользователей по вхождению строки в отображаемое имя или адрес почты без
учёта регистра и SHALL возвращать не более двадцати результатов. Пустая строка поиска SHALL
возвращать двадцать пользователей с самым свежим входом.

#### Scenario: Поиск по части имени

- GIVEN пользователь вводит часть имени коллеги
- WHEN выполняется поиск
- THEN возвращаются совпадения по имени и по адресу почты, не больше двадцати

#### Scenario: Пустая строка поиска

- GIVEN пользователь открывает выбор человека, ничего не введя
- WHEN выполняется поиск с пустой строкой
- THEN возвращаются двадцать пользователей, входивших недавно

### Requirement: Область видимости ограничивает результаты поиска

Система SHALL ограничивать результаты поиска людьми, связанными с зоной иерархии ищущего.
Связанной SHALL считаться зона, состоящая из узлов области видимости, всех их предков и всех их
потомков. В результаты SHALL попадать пользователь, у которого есть грант на любой узел этой
зоны, либо который назначен руководителем любой команды этой зоны.

#### Scenario: Коллега по соседней ветке

- GIVEN пользователь ищет человека, все гранты которого лежат в не связанной с ним ветке иерархии
- WHEN выполняется поиск
- THEN этот человек в результатах отсутствует

#### Scenario: Руководитель вышестоящей команды

- GIVEN человек назначен руководителем команды-предка узла из области видимости ищущего
- WHEN выполняется поиск
- THEN он попадает в результаты, даже если явных грантов у него нет

#### Scenario: Пользователь без области видимости

- GIVEN у ищущего нет ни одного выданного узла иерархии
- WHEN он выполняет поиск
- THEN возвращается пустой список

### Requirement: Администратор ищет без ограничения

Система SHALL возвращать администратору пространства результаты поиска по всему пространству без
ограничения зоной иерархии.

#### Scenario: Поиск администратором

- GIVEN администратор пространства
- WHEN он ищет человека
- THEN результаты не ограничиваются его грантами

### Requirement: Сужение поиска до одной команды

Система SHALL позволять сузить поиск до конкретной команды. Команда MUST быть доступна
ищущему; обращение к недоступной команде SHALL отклоняться.

#### Scenario: Поиск в доступной команде

- GIVEN пользователю доступна команда
- WHEN он ищет людей, сузив поиск до этой команды
- THEN зона поиска строится от этой команды, а не от всей его области видимости

#### Scenario: Поиск в недоступной команде

- GIVEN команда недоступна пользователю
- WHEN он сужает поиск до неё
- THEN запрос отклоняется

### Requirement: Публичный идентификатор пользователя

Система SHALL использовать в справочнике и во всех публичных ответах устойчивый строковый
идентификатор пользователя. Внутренний числовой идентификатор MUST NOT раскрываться.

#### Scenario: Ссылка на пользователя в ответе

- GIVEN ответ содержит ссылку на автора замечания или руководителя команды
- WHEN клиент разбирает ответ
- THEN пользователь адресуется строковым публичным идентификатором

### Requirement: Команда, которой человек руководит

Система SHALL сопровождать пользователя в справочнике названием команды, которой он руководит,
если такая есть. Учитываться SHALL только активные команды. Если человек руководит несколькими
командами, SHALL указываться первая по алфавиту.

#### Scenario: Руководитель одной команды

- GIVEN человек назначен руководителем активной команды
- WHEN он возвращается в справочнике
- THEN рядом с ним указано название этой команды

#### Scenario: Руководитель нескольких команд

- GIVEN человек руководит тремя активными командами
- WHEN он возвращается в справочнике
- THEN указывается первая из них по алфавиту

#### Scenario: Руководитель удалённой команды

- GIVEN единственная команда человека мягко удалена
- WHEN он возвращается в справочнике
- THEN команда руководства не указывается

### Requirement: Справочник доступен любому участнику

Система SHALL предоставлять справочник любому авторизованному участнику пространства без
требования роли администратора.

#### Scenario: Обычный участник выбирает драйвера цели

- GIVEN участник без роли администратора
- WHEN он открывает выбор драйвера цели
- THEN справочник доступен ему в пределах его зоны иерархии
