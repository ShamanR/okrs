# Personal Workspace Preferences Specification

## Purpose

Персональная настройка рабочего места: какие узлы иерархии участник хочет видеть в навигации
трекера и какие описания команд он держит перед глазами. Обе настройки сегодня персональны,
живут в браузере участника и не изменяют общие данные пространства.

## Requirements

### Requirement: Разделы личных настроек

Система SHALL предоставлять авторизованному участнику разделы личных настроек: описания команд,
уведомления, настройку навигации и список своих пространств. Активный раздел SHALL отражаться в
адресе страницы и восстанавливаться при возврате.

#### Scenario: Возврат в последний раздел

- GIVEN участник открывал раздел настройки навигации
- WHEN он открывает личные настройки заново без параметров в адресе
- THEN открывается тот же раздел

#### Scenario: Переходы по истории браузера

- GIVEN участник последовательно открыл несколько разделов
- WHEN он нажимает «назад»
- THEN восстанавливается предыдущий раздел без перезагрузки страницы

### Requirement: Раздел описаний команд доступен только руководителю

Система SHALL показывать раздел описаний команд только участнику, который назначен
руководителем хотя бы одной команды в своей области видимости. Остальным раздел SHALL быть
недоступен для выбора.

#### Scenario: Участник без команд руководства

- GIVEN участник не руководит ни одной командой
- WHEN он открывает личные настройки
- THEN раздел описаний команд ему не предлагается

#### Scenario: Руководитель открывает раздел

- GIVEN участник руководит командой
- WHEN он открывает раздел описаний
- THEN он видит свою команду и все вложенные в неё команды

### Requirement: Ограничение раздела описаний проверяется только на стороне клиента

Система сегодня SHALL определять право на раздел описаний команд сравнением участника с
руководителем узла в пределах уже выданной ему области видимости, и это единственная проверка.
Серверной записи описаний из этого раздела не происходит, поэтому отдельной серверной проверки
для него нет.

#### Scenario: Отсутствие серверной мутации

- GIVEN участник редактирует описание команды в личных настройках
- WHEN он сохраняет изменение
- THEN общие данные команды не изменяются и другим участникам новое описание не видно

### Requirement: Описание команды как персональный слой поверх общего

Система SHALL показывать в разделе описаний действующее описание команды как персональное
значение участника, если он его задал, иначе — общее описание команды. Персональное значение
SHALL применяться только к его собственному отображению.

#### Scenario: Персональное описание задано

- GIVEN участник сохранил своё описание команды
- WHEN он открывает трекер
- THEN он видит своё описание вместо общего

#### Scenario: Персональное описание не задано

- GIVEN участник не менял описание команды
- WHEN он открывает раздел описаний
- THEN отображается общее описание команды

### Requirement: Редактор описания с разметкой

Система SHALL предоставлять для описания команды редактор с поддержкой разметки и
предпросмотром, с сохранением и отменой правки. Кнопка входа в редактирование SHALL называться
одинаково независимо от того, задано описание или нет.

#### Scenario: Правка описания

- GIVEN участник открыл раздел описаний
- WHEN он входит в редактирование и вводит текст с разметкой
- THEN предпросмотр показывает результат до сохранения, а отмена возвращает прежнее значение

### Requirement: Выбор узлов навигации

Система SHALL предоставлять участнику дерево выбора узлов иерархии для навигации трекера. У
каждого узла SHALL быть три состояния: ничего в поддереве не выбрано, выбрано всё поддерево,
выбрана только часть. Нажатие на узел SHALL циклически переключать: ничего не выбрано → всё
поддерево → только сам узел → ничего не выбрано.

#### Scenario: Выбор всей ветви

- GIVEN узел с потомками не выбран
- WHEN участник нажимает на него
- THEN выбираются сам узел и все его потомки

#### Scenario: Сужение до самого узла

- GIVEN выбрано всё поддерево узла
- WHEN участник нажимает на него ещё раз
- THEN остаётся выбран только сам узел, потомки снимаются

#### Scenario: Частичный выбор

- GIVEN у узла выбрана только часть потомков
- WHEN участник смотрит на его состояние
- THEN узел отображается признаком частичного выбора

### Requirement: Правило видимости узла в навигации

Система SHALL показывать в навигации трекера узел, если он выбран участником либо содержит
выбранного потомка — родительские узлы сохраняются для навигации. Текущая открытая команда SHALL
быть видна всегда. Если выбор ни разу не настраивался, SHALL показываться вся доступная участнику
иерархия.

#### Scenario: Родитель невыбранного узла

- GIVEN участник выбрал только глубоко вложенную команду
- WHEN он открывает трекер
- THEN промежуточные родительские узлы остаются видимыми для навигации

#### Scenario: Переход в невыбранную команду

- GIVEN участник открывает по ссылке команду, которую он не выбирал
- WHEN отображается навигация
- THEN текущая команда видна, несмотря на её отсутствие в выборе

#### Scenario: Выбор не настраивался

- GIVEN участник ни разу не открывал настройку навигации
- WHEN он открывает трекер
- THEN отображаются все доступные ему узлы

### Requirement: Работа с большим деревом выбора

Система SHALL предоставлять в дереве выбора поиск по названию с показом пути найденного узла,
действия «выбрать все» и «снять все», сворачивание и разворот ветвей, счётчик выбранных узлов и
счётчик узлов, попадающих в навигацию.

#### Scenario: Поиск узла

- GIVEN участник вводит часть названия команды
- WHEN список фильтруется
- THEN найденные узлы показываются вместе с их путём в иерархии, независимо от свёрнутости веток

#### Scenario: Счётчик отличается от числа выбранных

- GIVEN участник выбрал вложенную команду
- WHEN он смотрит на счётчики
- THEN число узлов в навигации больше числа выбранных, потому что учитываются родительские узлы

### Requirement: Персональные настройки рабочего места хранятся в браузере участника

Система сегодня SHALL хранить персональные описания команд и выбор узлов навигации локально в
браузере участника, раздельно для каждого пользователя. Значения SHALL переживать перезагрузку
страницы и SHALL читаться трекером из того же источника, что и разделом настроек. На сервер эти
значения не передаются.

#### Scenario: Перезагрузка страницы

- GIVEN участник настроил выбор узлов навигации
- WHEN он перезагружает страницу
- THEN выбор сохраняется

#### Scenario: Другой браузер или устройство

- GIVEN участник настроил рабочее место в одном браузере
- WHEN он открывает приложение в другом браузере
- THEN настройки там отсутствуют и применяется поведение по умолчанию

#### Scenario: Два участника на одном устройстве

- GIVEN на одном устройстве работали два разных участника
- WHEN каждый открывает свои настройки
- THEN каждый видит собственные значения

### Requirement: Обязательные состояния разделов

Система SHALL отображать состояние загрузки при инициализации, заглушку ошибки при сбое
загрузки, сообщение о недоступности редактирования для участника без команд руководства и
сообщение о пустом результате поиска.

#### Scenario: Пустой поиск

- GIVEN участник ввёл строку, которой не соответствует ни один узел
- WHEN список фильтруется
- THEN отображается сообщение об отсутствии совпадений

### Requirement: Личные настройки рабочего места не зависят от статуса команды в периоде

Система MUST NOT связывать доступность разделов личных настроек рабочего места со статусом
команды в периоде.

#### Scenario: Закрытый период

- GIVEN все команды участника находятся в статусе «закрыт»
- WHEN он открывает личные настройки рабочего места
- THEN разделы доступны как обычно
