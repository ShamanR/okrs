# Goal Linking Specification

## Purpose

Связь целей соединяет две цели отношением «дочерняя → родительская» и позволяет декомпозировать
годовую цель или цель руководителя на цели команд и кварталов. Связь не делает цель общей, не
влияет на прогресс и не меняет видимость цели командами.

## Requirements

### Requirement: Связь как отношение декомпозиции

Система SHALL хранить связь между двумя различными целями как отношение «дочерняя →
родительская». Цель SHALL иметь возможность иметь несколько родителей и несколько потомков.

#### Scenario: Привязка к двум родителям

- GIVEN у пользователя есть доступ к цели и к двум родительским целям
- WHEN он привязывает цель к обеим родительским целям
- THEN обе связи сохраняются

### Requirement: Сохранение набора родителей целиком

Система SHALL принимать набор родительских целей целиком: родители, отсутствующие в новом
наборе, SHALL отвязываться.

#### Scenario: Замена набора родителей

- GIVEN у цели есть родители P1 и P2
- WHEN сохраняется набор, состоящий только из P2 и P3
- THEN связь с P1 снимается, связь с P3 добавляется, связь с P2 сохраняется

### Requirement: Запрет самоссылки

Система SHALL отклонять как ошибку валидации попытку сделать цель собственным родителем.

#### Scenario: Цель как собственный родитель

- GIVEN пользователь редактирует связи цели
- WHEN он указывает эту же цель в качестве родительской
- THEN операция отклоняется как ошибка валидации

### Requirement: Граф связей ацикличен

Система SHALL отклонять как конфликт добавление связи, замыкающей цикл, включая транзитивный.

#### Scenario: Прямой цикл

- GIVEN цель A является родителем цели B
- WHEN пользователь указывает цель B родителем цели A
- THEN операция отклоняется как конфликт

#### Scenario: Транзитивный цикл

- GIVEN цель A является предком цели C по цепочке связей
- WHEN пользователь указывает цель C родителем цели A
- THEN операция отклоняется как конфликт

### Requirement: Связи ограничены одним пространством

Система SHALL требовать, чтобы обе цели связи принадлежали одному пространству. Межпространственные
связи MUST NOT создаваться.

#### Scenario: Родитель из другого пространства

- GIVEN пользователь указывает родительскую цель другого пространства
- WHEN запрос обрабатывается
- THEN операция отклоняется, связь не создаётся

### Requirement: Видимость связей ограничена областью видимости читателя

Система SHALL включать связанную цель в ответ только если её команда-владелец доступна читателю.
Связь на недоступную команду SHALL быть скрыта — для читателя такой связи не существует.

#### Scenario: Родитель в недоступной команде

- GIVEN у цели есть родительская цель в команде вне области видимости читателя
- WHEN читатель открывает цель
- THEN эта связь и эта родительская цель ему не показываются

#### Scenario: Счётчики связей учитывают только доступное

- GIVEN у цели три потомка, из которых один в недоступной читателю команде
- WHEN читатель видит метку числа связей
- THEN метка показывает два потомка

### Requirement: Проверка доступа при изменении связей

Система SHALL проверять на сервере доступ к команде-владельцу дочерней цели и доступность каждой
указанной родительской цели.

#### Scenario: Изменение связей недоступной цели

- GIVEN команда-владелец дочерней цели недоступна пользователю
- WHEN он пытается изменить её связи
- THEN возвращается «не найдено», связи не меняются

### Requirement: Связь не влияет на прогресс и видимость

Система MUST NOT учитывать связи при расчёте прогресса и MUST NOT изменять из-за связи
видимость цели командами. Связь навигационная.

#### Scenario: Прогресс родителя не зависит от потомков

- GIVEN у цели есть дочерние цели с высоким прогрессом
- WHEN вычисляется прогресс родительской цели
- THEN он определяется только её собственными ключевыми результатами

#### Scenario: Связь не даёт доступа

- GIVEN цель связана с целью команды, недоступной пользователю
- WHEN пользователь открывает свою цель
- THEN доступ к недоступной команде он не получает

### Requirement: Связи не зависят от статуса команды в периоде

Система SHALL разрешать привязку и отвязку родительских целей во всех статусах команды в
периоде.

#### Scenario: Изменение связей в статусе «закрыт»

- GIVEN статус команды в периоде — «закрыт»
- WHEN пользователь привязывает цель к родительской цели
- THEN связь сохраняется

### Requirement: Связи не переживают удаление цели и не копируются

Система SHALL удалять связи цели вместе с самой целью, в том числе при переносе цели. Связи MUST
NOT копироваться при копировании или переносе цели.

#### Scenario: Удаление связанной цели

- GIVEN у цели есть родители и потомки
- WHEN цель удаляется
- THEN все её связи исчезают, а связанные цели сохраняются

#### Scenario: Копирование связанной цели

- GIVEN у исходной цели есть родители
- WHEN она копируется в другую команду
- THEN новая цель создаётся без связей

### Requirement: Подбор родительской цели

Система SHALL предлагать при выборе родительской цели список доступных целей, сгруппированный
по командам, с фильтром по периоду (включая режим «все периоды») и поиском по названию цели,
названию команды или имени руководителя. Уже выбранные цели SHALL отображаться отмеченными и
недоступными для повторного выбора.

#### Scenario: Поиск кандидата

- GIVEN пользователь открывает подбор родительской цели
- WHEN он вводит часть названия команды
- THEN список сужается до целей этой команды, сгруппированных по командам

### Requirement: Отображение связей у карточки цели

Система SHALL показывать у карточки цели метку числа родителей и метку числа потомков, а при
наведении раскрывать список связанных целей с переходом к каждой из них.

#### Scenario: Переход по связи

- GIVEN у цели есть родительская цель
- WHEN пользователь раскрывает список связей и выбирает родительскую цель
- THEN он переходит на доску команды этой цели
