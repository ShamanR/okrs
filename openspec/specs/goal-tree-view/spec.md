# Goal Tree View Specification

## Purpose

Дерево целей визуализирует граф декомпозиции: как годовые цели раскладываются в квартальные, а
цели руководителей — в цели команд. Раздел доступен только для чтения и не меняет данные.

## Requirements

### Requirement: Граф целей и связей

Система SHALL отображать цели вершинами, а связи «дочерняя → родительская» — рёбрами,
направленными сверху вниз от родительской цели к дочерней. Граф SHALL быть ациклическим.

#### Scenario: Просмотр декомпозиции

- GIVEN годовая цель связана с двумя квартальными
- WHEN пользователь открывает дерево целей
- THEN годовая цель отображается выше, а от неё вниз идут рёбра к квартальным

### Requirement: Раздел доступен любому участнику и только для чтения

Система SHALL предоставлять дерево целей любому авторизованному участнику пространства, без
требования роли администратора, и MUST NOT предоставлять в нём операций изменения данных.

#### Scenario: Участник открывает раздел

- GIVEN участник без роли администратора пространства
- WHEN он открывает дерево целей
- THEN раздел отображается в пределах его области видимости

### Requirement: Горизонтальные полосы по гранулярности периода

Система SHALL размещать цель в горизонтальной полосе, соответствующей глубине её периода:
корневые периоды — верхняя полоса, вложенные — ниже по возрастанию глубины. Отдельная нижняя
полоса SHALL собирать цели без родителей и без потомков.

#### Scenario: Годовые и квартальные цели

- GIVEN выбраны цели годового и квартального периодов
- WHEN отображается граф
- THEN годовые цели находятся в верхней полосе, квартальные — в полосе ниже

#### Scenario: Пустая полоса «Без связей»

- GIVEN среди отображаемых целей нет целей без связей
- WHEN отображается граф
- THEN полоса «Без связей» не показывается

### Requirement: Визуальные группы целей одной команды

Система SHALL объединять в визуальную группу цели, которые принадлежат одной команде и при этом
связаны друг с другом или с общей родительской целью. Группа — презентационный контейнер и MUST
NOT быть сущностью данных.

#### Scenario: Цели одной команды под общим родителем

- GIVEN у одной команды есть три цели, связанные с общей родительской целью
- WHEN отображается граф
- THEN эти три цели визуально объединены в один контейнер

### Requirement: Выделение корневых целей

Система SHALL визуально выделять цели, у которых в области видимости читателя нет родителей.

#### Scenario: Корневая цель на холсте

- GIVEN у цели нет доступных читателю родителей
- WHEN отображается граф
- THEN эта цель выделена среди остальных

### Requirement: Выбор цели подсвечивает связанное дерево

Система SHALL при выборе цели подсвечивать все связанные с ней цели транзитивно вверх и вниз и
одновременно открывать её расширенную карточку только для чтения.

#### Scenario: Клик по цели

- GIVEN на холсте несколько связных компонент
- WHEN пользователь выбирает цель
- THEN подсвечивается всё связанное с ней дерево и открывается панель с её деталями

#### Scenario: Изоляция поддерева

- GIVEN открыта расширенная карточка цели
- WHEN пользователь выбирает «скрыть остальные цели»
- THEN на холсте остаётся только поддерево выбранной цели вверх и вниз

### Requirement: Сворачивание поддерева на карточке

Система SHALL позволять свернуть на карточке нижестоящее поддерево. Сворачиваться SHALL только
цели, у которых нет других видимых родителей.

#### Scenario: Сворачивание при общем потомке

- GIVEN у дочерней цели есть два видимых родителя
- WHEN пользователь сворачивает поддерево одного из них
- THEN дочерняя цель остаётся видимой

### Requirement: Выбор периода в разделе

Система SHALL предоставлять в разделе селектор периода, отражать выбор в адресе страницы и
восстанавливать его по тем же правилам приоритета: параметр адреса, затем сохранённое значение,
затем первый доступный период.

#### Scenario: Ссылка на дерево с периодом

- GIVEN пользователь выбрал период в дереве целей
- WHEN он передаёт адрес страницы
- THEN получатель открывает дерево с тем же периодом

### Requirement: Ограничение графа выбранным периодом

Система SHALL по умолчанию показывать только цели выбранного периода и всех вложенных в него
периодов, обрезая рёбра к целям вне этого набора.

#### Scenario: Выбран годовой период

- GIVEN выбран годовой период, внутри которого есть кварталы
- WHEN отображается граф
- THEN видны цели года и его кварталов, а связи к целям других периодов не рисуются

### Requirement: Режим связей между периодами

Система SHALL предоставлять переключатель, который добавляет к базовому набору целей
транзитивно связанные цели из других периодов. Режим MUST NOT означать показ всех периодов:
добавляются только цели, реально связанные с выбранной веткой. По умолчанию режим выключен.

#### Scenario: Включение связей между периодами

- GIVEN цель выбранного периода связана с целью другого периода
- WHEN пользователь включает режим связей между периодами
- THEN связанная цель другого периода появляется на холсте вместе с ребром

### Requirement: Фильтры графа

Система SHALL предоставлять фильтры: скрытие целей без связей (включён по умолчанию),
«мои цели» — оставить только ветки, где есть команда с текущим пользователем в роли руководителя
(включён по умолчанию), выбор конкретной корневой цели и режим «только корневые цели».

#### Scenario: Фильтр «мои цели»

- GIVEN на холсте есть ветки без команд пользователя
- WHEN включён фильтр «мои цели»
- THEN остаются только ветки, содержащие хотя бы одну команду, которой руководит пользователь

#### Scenario: Список корневых целей строится из отфильтрованного набора

- GIVEN применены фильтры периода и «мои цели»
- WHEN пользователь раскрывает список корневых целей
- THEN предлагаются только корни, присутствующие в текущем виде

#### Scenario: Сброс выбранного корня

- GIVEN выбран конкретный корень, затем сменён период
- WHEN выбранный корень выпадает из набора
- THEN фильтр по корню сбрасывается, граф не остаётся пустым

### Requirement: Детерминированный порядок применения фильтров

Система SHALL применять фильтры в фиксированном порядке: период и режим связей между периодами;
скрытие полосы «Без связей»; «мои цели»; фильтр по выбранному корню; режим «только корневые
цели»; свёрнутые поддеревья и изоляция выбранного поддерева.

#### Scenario: Одинаковый результат при одинаковых настройках

- GIVEN пользователь задаёт набор фильтров
- WHEN он повторяет тот же набор в другом порядке переключения
- THEN итоговый граф совпадает

### Requirement: Сохранение настроек графа

Система SHALL сохранять значения переключателей раздела локально в браузере и применять
значения по умолчанию при первом заходе и для неизвестных значений. Источником истины для
выбранного периода SHALL оставаться адрес страницы.

#### Scenario: Повторное открытие раздела

- GIVEN пользователь изменил переключатели фильтров
- WHEN он открывает раздел заново
- THEN переключатели восстанавливаются в его значениях

### Requirement: Обязательные состояния раздела

Система SHALL отображать состояние загрузки при инициализации и смене периода, состояние ошибки
с возможностью повтора и состояние «нет целей со связями», когда после применения фильтров граф
пуст.

#### Scenario: Пустой граф после фильтров

- GIVEN после применения фильтров ни одна цель не проходит
- WHEN раздел отображается
- THEN показывается сообщение об отсутствии целей со связями, а не пустой холст

#### Scenario: Ошибка загрузки

- GIVEN данные графа не удалось загрузить
- WHEN раздел отображается
- THEN показывается заглушка ошибки с возможностью повторить загрузку

### Requirement: Ограничение графа областью видимости

Система SHALL исключать из ответа цели недоступных читателю команд и связи на них. Признак
«моя цель» SHALL вычисляться на сервере; идентификаторы руководителей команд MUST NOT
выноситься на клиент.

#### Scenario: Цель недоступной команды

- GIVEN цель принадлежит недоступной читателю команде
- WHEN читатель открывает дерево целей
- THEN ни цель, ни ведущие к ней рёбра не отображаются
