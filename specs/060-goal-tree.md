# Goal Tree (Дерево целей)

Раздел визуализирует граф зависимостей целей — как годовые/квартальные цели
декомпозируются друг в друга через связи `goal_links` (см. `020-domain-model.md` →
`GoalLink`). Живёт на маршруте `/goal-tree`, доступен любому аутентифицированному
участнику тенанта (как `/settings`, не под admin-гейтом). Ранее `/goal-tree` был
страницей-заглушкой (`stub-shell` + `stub.js`) — эта спека заменяет заглушку реальной
функциональностью.

## Классификация фичи (по требованиям `030-user-flows.md` / `050-permissions-and-lifecycle.md`)

- **Страница:** `/goal-tree` (новый SPA-shell `goal-tree-shell` + `goal_tree.js` + `goal_tree.css`).
- **Механика данных:** **API hydration** (read-only). Мутаций нет — раздел только читает
  и визуализирует уже существующие цели и связи.
- **Зависимость от `team period status`:** нет. Граф строится по целям и связям независимо
  от статуса команды в периоде.
- **Зависимость от auth mode / роли:** доступен любому аутентифицированному участнику;
  при `AUTH_MODE=disabled` — всем (как обычно, от `anonymous-local`). Роль (`admin`/`user`)
  на доступ к разделу не влияет; влияет только hierarchy scope (что видно).
- **Где проверяется ограничение:** **на сервере**. Видимость целей, команд и связей
  ограничена tenant + hierarchy grants на стороне API; клиент лишь отображает пришедшее.
- **Зависимость от будущих permissions / roles:** нет; опирается на текущую модель
  tenant + hierarchy grants.

## Модель графа

### Вершины и рёбра

- **Вершина** — цель (`Goal`). На графе представлена карточкой цели.
- **Ребро** — связь `goal_links` «дочерняя → родительская» (декомпозиция). Граф
  направленный, рисуется сверху вниз: родительская цель выше, дочерняя ниже.
- Граф — DAG (гарантируется инвариантом `goal_links`, см. `020-domain-model.md`).
- **Scope-фильтрация (source of truth — сервер):** цель попадает в граф, только если её
  команда-владелец доступна читателю (grant/админ, tenant). Связь на недоступную команду
  **скрывается** — считается, что связи нет, ребро не рисуется. Это консистентно с тем,
  что цель недоступной команды = `404` в остальном API.

### Слои (бэнды)

Граф разделён на **горизонтальные бэнды по гранулярности периода**. Гранулярность =
`Period.depth` (глубина вложенности периода, вычисляется сервером, см. `020-domain-model.md`):

- бэнд `depth = 0` — верхний (годовые цели);
- бэнд `depth = 1` — ниже (квартальные цели);
- глубже — свои бэнды в порядке возрастания `depth` (если такие периоды выбраны/показаны);
- отдельный нижний бэнд **«Без связей»** — цели без родителей и без детей (в scope читателя).

Правила бэндов:

- бэнд «Без связей» **скрывается**, если он пуст **или** включён контрол «Скрыть цели без
  связи»;
- вертикальное положение карточки определяется бэндом её периода; **внутри** бэнда позиция
  дополнительно уточняется глубиной цели в дереве связей (для случаев, когда связанные цели
  оказались в одном бэнде);
- **корневые цели** (без родителей в scope) визуально ярко выделяются на фоне остальных.

### Группы

Цели объединяются в **визуальную группу** (обведённый контейнер), если они:

- принадлежат **одной и той же команде**, **И**
- ссылаются друг на друга **или** на одну общую (родительскую) цель.

Группа — чисто презентационный контейнер (не сущность БД). Группа отличается от
**подсветки дерева по клику** (см. ниже): группа локальна (одна команда, общий родитель),
а подсветка — транзитивная по всем связям.

## Раскладка (layout) — клиентская

Раскладка реализуется **своим layered-движком на plain JS** (без сторонних графовых
библиотек — в `vendor/` их нет, проект без сборщика и без CDN). Движок — чистая функция
`граф → { bands[], nodes[], edges[], groups[] }`, отделённая от React-рендера и от загрузки
данных (изолируемость и тестируемость).

- **Y (бэнды):** карточка располагается в бэнде своего периода по `Period.depth`; бэнд
  «Без связей» — снизу.
- **X (упорядочивание):** по связным компонентам; внутри компоненты дочерние карточки
  выравниваются под родительскими, порядок внутри бэнда минимизирует пересечения рёбер
  (барицентр-эвристика по слоям). Группы одной команды держатся рядом.
- **Рёбра:** ортогональные (квадратные) SVG-пути со скруглёнными углами, направленные
  сверху (родитель) вниз (ребёнок).
- **Слои рендера:** SVG-слой рёбер + слой групп-контейнеров + слой HTML-карточек поверх;
  всё в общем прокручиваемом/зумируемом холсте.

## Карточки

- **Узловая карточка** (`GoalTreeCard`) — компактная, переиспользует визуальный язык трекера
  (progress-bar, бейджи приоритета/типа работы/фокуса), но **не** тянет тяжёлый редактируемый
  `GoalCard` (без inline-редактирования, KR, комментариев). Корневые цели — акцентный стиль.
- На карточке есть **кнопка-collapse**, скрывающая рёбра графа вниз и сворачивающая
  исключительно-нижестоящее поддерево (цели, у которых нет других видимых родителей).
- **Клик по карточке** делает две вещи одновременно:
  1. подсвечивает всё связанное дерево (транзитивно вверх и вниз от выбранной цели);
  2. открывает **расширенную карточку** цели (read-only панель с деталями).
- **Расширенная карточка** содержит кнопку **«Скрыть остальные цели»** — оставляет на
  холсте только поддерево выбранной цели (вверх и вниз), пряча остальное.

## Контролы

### Над графом

- **«Показать только корневые цели»** — скрывает всё, кроме корневых целей (без детей на
  холсте).

### В сайдбаре

- **Селектор периода** (верхний слот сайдбара, `beforeSections`, как в трекере) — выбор
  текущего периода из `GET /api/v1/periods` (пункты с отступом по `depth` и статус-индикатором).
  Выбранный период живёт в URL — `/goal-tree?period=<id>` (общий контракт `period_url.js`, см.
  `030-user-flows.md`, `3е`): ссылку можно переслать, «Назад»/«Вперёд» возвращают предыдущий выбор.
  Приоритет при загрузке: `?period` (если такой период есть в списке) → сохранённое значение
  (`localStorage`, `okr_goaltree_period`) → первый доступный. Значение продолжает сохраняться в
  `localStorage`, но используется только при заходе без параметра.
- **Связи между периодами** — дефолт **выкл**. Управляет тем, ограничен ли граф выбранным
  периодом и его вложенными, или дотягивает связанные цели из других периодов:
  - **выкл** → показываются **только цели выбранного периода и всех его вложенных** (потомков по
    дереву периодов, `parent_id`); напр. выбран годовой период → видны и его кварталы. Рёбра к
    целям вне этого набора обрезаются (межпериодные связи не рисуются).
  - **вкл** → к базовому набору (выбранный период + вложенные) **транзитивно добавляются
    связанные цели вверх и вниз**, в том числе из других периodов (связные компоненты, касающиеся
    базового набора). Это **не** «все непархивированные периоды» — подтягиваются только цели,
    реально связанные с выбранной веткой.
- **Скрыть цели без связи** — дефолт **вкл**. Убирает бэнд «Без связей».
- **Мои цели** — дефолт **вкл**. Оставляет только связные ветки, в которых есть хотя бы одна
  команда, где текущий пользователь — руководитель (`led_by_me`, см. API). Ветка = связная
  компонента графа.
- **Выпадающий список корневых целей** — для фильтрации по конкретному корню. Список строится из
  **уже отфильтрованного** набора (после фильтра периода + «Мои цели»/«Скрыть без связи», но до
  самого root-фильтра) — предлагаются только реально доступные в текущем виде корни, чтобы выбор
  не приводил к пустому графу; если выбранный корень выпадает из набора (сменили период/«Мои
  цели») — он сбрасывается. Отображается **древовидно** согласно иерархии команд: показываются
  команды с корневыми целями и все их предки-заголовки (без целей), отступы по `teams[].parent_id`;
  цели команды — на один уровень глубже её заголовка. Выбор фильтрует граф до поддерева выбранного
  корня; пустой выбор — без фильтра.

### Персистентность

Значения тумблеров сохраняются локально в браузере (`localStorage`, ключи с префиксом
`okr_goaltree_*` через общий `storage.js`). Выбранный период персистится там же
(`okr_goaltree_period`), но источник истины для него — URL (`?period=<id>`), а сохранённое
значение служит fallback'ом при заходе без параметра.
Дефолты применяются при первом заходе / для неизвестных значений: связи между периодами — выкл,
скрыть цели без связи — вкл, мои цели — вкл; период — из URL, иначе восстановленный или первый
доступный.
Серверные данные и схема БД не меняются.

## Порядок применения фильтров (детерминированность)

Клиент один раз запрашивает **весь** граф в scope (`GET /api/v1/goal-tree?cross_period=1` —
все непархивированные периoды), а выбор периода и тумблеры применяет **на клиенте** (без
рефетча). Фильтры применяются в фиксированном порядке над этим набором (уже
tenant/scope-фильтрованным сервером):

1. **фильтр по периоду** (селектор периода + «Связи между периodами»): базово — цели выбранного
   периода и его вложенных; при включённом тумблере — плюс транзитивно связанные цели из других
   периodов (см. раздел «Контролы»). Рёбра пересчитываются на присутствующие цели;
2. скрытие бэнда «Без связей» (контрол «Скрыть цели без связи»);
3. «Мои цели» — оставить только ветки с `led_by_me`;
4. фильтр по выбранному корню из выпадающего списка;
5. «Показать только корневые цели»;
6. свёрнутые поддеревья (collapse-кнопки на карточках) и режим «Скрыть остальные цели».

## Состояния (обязательные)

- **loading** — «Загрузка…» при инициализации/смене периода;
- **error** — заглушка ошибки с кнопкой «Повторить»;
- **empty** — «Нет целей со связями» (когда после scope/фильтров граф пуст).

## Доступ, тенанты, edge-cases

- Соблюдается видимость и доступ к командам: недоступные команды и их цели/связи не приходят
  с сервера; скрытая связь = «связи нет», ребро не рисуется.
- Работа строго в рамках активного тенанта (`TenantScopeFromContext`).
- «Мои цели» опирается на серверный флаг `led_by_me` (сервер сравнивает `lead_udid` команды с
  UDID вызывающего) — сырой `lead_udid` на клиент не выносится (не утекает PII руководителей).
