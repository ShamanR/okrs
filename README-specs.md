# README Specs

Этот каталог описывает правила разработки проекта **OKRs** в формате spec-based development.

Цель этих документов — сократить число итераций при работе с AI и сделать изменения в проекте более предсказуемыми:

- каждая существенная фича сначала описывается в спецификации;
- AI реализует изменения только в рамках явного scope;
- архитектурные, доменные и продуктовые ограничения фиксируются отдельно от кода;
- любая новая функциональность опирается на единый шаблон spec-документа.

---

## Структура

```text
/specs
  000-product-overview.md
  010-architecture-constraints.md
  020-domain-model.md
  030-user-flows.md
  040-api-contract.md
  050-permissions-and-lifecycle.md
  070-code-structure.md
```

`070-code-structure.md` отвечает на вопрос «где лежит код»: раскладка пакетов по
слоям и карта «URI → пакет обработчика». `010-architecture-constraints.md` —
на вопрос «кому что можно вызывать».

Каналы уведомлений расширяемы через публичный пакет `notifychannel` и
подключаются значением рядом с `main` (`app.Config.NotificationChannels`), а не
регистрацией в `init()`.
