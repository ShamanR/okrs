# Копирование ссылки на цель

Дата: 2026-07-19

## Проблема

Пользователь не может быстро поделиться ссылкой на конкретную цель. Deep-link
механизм в трекере уже существует (лог активности и колокольчик Health Check-in
строят ссылки вида `/?team=<id>&period=<id>&goal=<id>`), но на самой карточке цели
нет элемента управления, чтобы скопировать такую ссылку.

## Цель

Добавить на карточку цели иконку «скопировать ссылку». Ссылка ведёт на цель
**в конкретном периоде конкретной команды**. Для расшаренной (общей) цели ссылка
ведёт на **ту же команду, в которой она собрана** (текущая открытая команда), а не
на команду-владельца.

## Scope

- **Страница:** трекер `/teamOkrs` (SPA, `tracker.js`).
- **Механизм:** чисто клиентский — ни API hydration, ни API mutation. Переиспользует
  существующий deep-link (`buildTargetURL` из `ui.js`, чтение параметров в
  `readURLNav`).
- **Не входит в scope:** серверные изменения, новые endpoint'ы, изменения схемы БД.

## Дизайн

### URL

Ссылка строится абсолютной, чтобы её можно было отправить коллеге:

```
location.origin + buildTargetURL({
  team_id:   currentTeamId,   // текущая открытая команда (selId)
  period_id: periodId,        // текущий выбранный период
  goal_id:   goal.id,
})
// → https://<host>/?team=<currentTeamId>&period=<periodId>&goal=<goalId>
```

- Переиспользуется общий помощник `buildTargetURL` из `ui.js` (тот же, что у лога
  активности и колокольчика) — единая конвенция URL по всему приложению.
- `/` отдаёт трекер (`server.go`), `/teamOkrs` редиректит на `/` с сохранением query,
  поэтому канонический вид ссылки — `/?...`.
- **Общая цель:** используется `currentTeamId` (открытая команда), поэтому ссылка
  всегда резолвится в ту команду, где была скопирована. Утечки на команду-владельца
  нет.
- **Эквивалентность логу активностей:** форма URL и поведение открытия идентичны
  переходу по «↗ к цели» из лога — та же `buildTargetURL`, то же чтение параметров
  (`readURLNav`), тот же scroll+flash к `goal-<id>`. Никаких отдельных веток обработки
  ссылки: копи-ссылка и ссылка из лога проходят один и тот же код открытия.

### Раскрытие дерева команд при открытии ссылки

Требование: при открытии ссылки дерево команд в сайдбаре должно **раскрыться на
целевой команде** — команда должна быть видимой (её предки развёрнуты), а не спрятана
под свёрнутым родителем.

Текущее поведение (gap): выбранная команда всегда рендерится
(`filterTreeForSidebar` держит `currentId`), но если пользователь ранее свернул узел-
предок (`expanded[ancestorId] === false`), целевая команда остаётся скрытой в дереве.
Тот же gap есть и у существующего deep-link из лога активностей.

Решение (общее для обеих ссылок): при инициализации из URL, когда `team` задан в URL и
найден в иерархии, развернуть всех его предков — проставить `expanded[ancestorId] = true`
(перекрывая возможный сохранённый `false`). Это делает открытие ссылки эквивалентным
для копи-ссылки и ссылки из лога и гарантирует видимость целевой команды в дереве.

- Раскрытие применяется **только** когда команда пришла из URL (не из cookie
  `okr_last`) — обычное переоткрытие приложения по cookie не ломает пользовательское
  состояние сворачивания.
- Нужен помощник `findAncestorIds(nodes, id)` (DFS по `children`), возвращающий id
  предков целевого узла.
- Точка внедрения — резолв целевой команды из URL в эффекте загрузки иерархии
  (там, где `initialNavRef.current.team` находится в дереве).

### Размещение (UI)

- Иконка-кнопка «скопировать ссылку» располагается **в конце строки** `.goal-card__meta`,
  **справа** от блока драйвера цели (`.goal-card__owner`).
- Кнопка рендерится **всегда**, независимо от наличия драйвера. `.goal-card__spacer`
  (`flex: 1`) держит правую группу прижатой вправо, поэтому «место» кнопки одинаково
  и с драйвером, и без него.
- Глиф — 🔗 (chain/link), в скруглённой кнопке, консистентно с остальными контролами
  карточки. `title` = «Скопировать ссылку на цель».

### Обратная связь при копировании

- `navigator.clipboard.writeText(url)`; при успехе иконка на ~1.5 c меняется на
  зелёную ✓ с `title`/подписью «Скопировано», затем возвращается к 🔗.
- Fallback для небезопасного контекста (нет `navigator.clipboard`): временный
  `<textarea>` + `document.execCommand('copy')`.
- При ошибке копирования состояние ✓ не показывается (иконка остаётся 🔗); отдельного
  error-стейта в UI не заводим — деградация тихая.

### Пропсы / данные

- `GoalCard` уже получает `currentTeamId={selId}`.
- Нужно дополнительно прокинуть **`periodId`** (текущий выбранный период) в `GoalCard`
  — сейчас его там нет.

## Состояния

- **loading / empty / error:** новых обязательных состояний нет (клиентская операция).
  Единственное транзиентное состояние — «Скопировано» (✓) после успешного копирования.

## Зависимости от контекста

- **team period status:** не зависит.
- **auth mode / роль:** не зависит — любой, кто видит цель, может скопировать ссылку.
- **Проверка ограничений:** только в UI; серверных ограничений нет и не требуется
  (ссылка не даёт доступа сверх того, что уже есть у получателя — при открытии
  применяется обычный scope-контроль команды).

## Тесты

- Фронтенд-фича без Go-логики; серверных тестов нет. Проверяется ручной верификацией
  в реальном приложении:
  - копирование даёт корректный URL (`/?team=&period=&goal=`);
  - открытие URL открывает нужную команду/период/цель, скроллит и подсвечивает цель
    (эквивалентно переходу из лога активностей);
  - для общей цели ссылка ведёт в текущую команду;
  - при открытии ссылки на команду под свёрнутым родителем дерево сайдбара
    раскрывается на целевой команде (предки развёрнуты, команда видна и подсвечена).
