# Дизайн: рефакторинг сайдбара (единый layout навигации)

Дата: 2026-07-10
Ветка: `sidebar-layout-refactoring`

## Цель

Убрать глобальное гамбургер-меню (`☰`) и развернуть его содержимое прямо в
тёмный сайдбар. Навигация становится единой и постоянно видимой на страницах
с тенант-контекстом: трекер, заглушки (goal-tree / activity-log), настройки,
админка.

Системная (superadmin) панель `system.js` в scope **не входит**: это
cross-tenant surface без сайдбара, без бургера и без понятия «текущий тенант»
(центрированный layout с табами). Единый тенант-сайдбар там неприменим.

## Мотивация / проблема

Сейчас глобальная навигация спрятана в выезжающем drawer'е (`HeaderNavMenu` из
`header.js`), который открывается кнопкой `☰` в левом верхнем углу сайдбара.
Разделы, переключатель тенанта, документация, обратная связь и аккаунт-блок
доступны только после клика по бургеру. Цель — сделать эту навигацию
постоянно видимой в сайдбаре и унифицировать её на всех страницах.

## Требования (из задачи)

1. Убрать бургер-меню.
2. Выбор/название текущего тенанта вывести вверх сайдбара.
3. Убрать кнопку Health Check-in; вместо неё — колокольчик справа от названия
   тенанта (переиспользует ту же панель Health Check-in).
4. Под выбором периода разместить ссылки на разделы.
5. Внизу сайдбара — информация о пользователе, ссылки на документацию и
   обратную связь.

## Принятые решения

- **Колокольчик** переиспользует существующий Health Check-in: клик открывает
  `HealthCheckInPanel`, бейдж = `total_problems`. Новый backend не нужен.
  Колокольчик показывается только на трекере (только там загружен период; при
  `!has_scope` скрыт — как сейчас кнопка).
- **Шапка тенанта** — только название + квадратный аватар с инициалами (из
  названия). Счётчики «84 КОМАНД · 1.2K» не выводим — данных нет в API.
- **Единый подход**: общий шаблон сайдбара применяется ко всем shell с
  тенант-контекстом (трекер, заглушки, settings, admin), бургер
  (`header.js` / `HeaderNavMenu`) удаляется отовсюду. `system.js` — вне scope.
- **Меню пользователя** («...» в футере): Настройки / Администрирование (для
  админов) / Выйти. Документация и Обратная связь — отдельными ссылками над
  блоком пользователя.

## Архитектура

Новый общий модуль **`internal/web/static/sidebar.js`**, подключаемый как
`text/babel` перед app-скриптами каждого shell (по образцу `header.js`).
Экспортирует контейнер-компонент и его части в глобальную область.

```
Sidebar({ user, cfg, active, bell, children })
  ├─ SidebarTenant({ user, bell })
  │     аватар-инициалы + название тенанта + шеврон (переключатель тенантов,
  │     если тенантов > 1, через POST /api/v1/session/tenant) + слот bell
  ├─ SidebarSections({ active })
  │     глобальные РАЗДЕЛЫ: Цели команды (/), Дерево целей (/goal-tree),
  │     Лог активностей (/activity-log); активный подсвечивается
  ├─ {children}
  │     контекстная навигация конкретной страницы
  └─ SidebarFooter({ user, cfg })
        Документация + Обратная связь (условно, из cfg) + блок пользователя
        (аватар, имя, email) с «...» → мини-меню (Настройки / Администрирование
        для админов / Выйти). Сюда же переезжает FeedbackNudge.
```

Единая двухуровневая структура на каждой странице:
**шапка тенанта → глобальные разделы → контекст страницы → футер.**

Стили выносятся в новый **`internal/web/static/sidebar.css`**, подключаемый во
всех shell.

### Данные

- Название/переключение тенанта: `GET /api/v1/session/tenants` (поля `name`,
  `active`), переключение — `POST /api/v1/session/tenant`. Аватар-инициалы
  вычисляются из `name` на клиенте.
- Документация / обратная связь / признак админа: `GET /api/v1/config`
  (`documentation_url`, `feedback_url`, `feedback_menu_link_enabled`,
  `is_admin`).
- Health Check-in (колокольчик, только трекер):
  `GET /api/v1/health-checkin?period_id=<id>` — как сейчас.

## Компоновка (сверху вниз, трекер)

```
┌─────────────────────────────┐
│ [ОП] Операции      ▾    🔔10 │  SidebarTenant (+ bell = Health Check-in)
├─────────────────────────────┤
│ ПЕРИОД                       │
│ [ Q1 · 2026            ▾ ]   │  контекст трекера (PeriodSelect)
├─────────────────────────────┤
│ РАЗДЕЛЫ                      │
│ ◎ Цели команды  (active)    │  SidebarSections
│ ⌥ Дерево целей              │
│ ∿ Лог активностей           │
├─────────────────────────────┤
│ КОМАНДЫ / Избранное / …      │  контекст трекера (дерево, flex:1, скролл)
├─────────────────────────────┤
│ 📖 Документация              │  SidebarFooter (прижат вниз)
│ ☆ Обратная связь            │
│ [АИ] Алексей Иванов    ...   │
└─────────────────────────────┘
```

Порядок «ПЕРИОД → РАЗДЕЛЫ» на трекере соответствует исходной задаче (п. 4:
ссылки на разделы под выбором периода).

## Контекстная часть (`children`) по страницам

| Страница | `children` (контекст) | `active` | Колокольчик |
|---|---|---|---|
| tracker (`/`) | ПЕРИОД (select) + КОМАНДЫ (дерево) | `tracker` | да |
| goal-tree | — | `goal-tree` | нет |
| activity-log | — | `activity-log` | нет |
| settings | «НАСТРОЙКИ»: Описания / Мой сайдбар / Пространства | — | нет |
| admin | «АДМИНИСТРИРОВАНИЕ»: Периоды / Команды / Пользователи / Настройки / Health Check-in | — | нет |

- Локальные «Разделы» settings/admin переименовываются в контекстные группы
  («НАСТРОЙКИ», «АДМИНИСТРИРОВАНИЕ»), чтобы не конфликтовать с глобальными
  РАЗДЕЛАМИ.
- Переходы между настройками / админкой / выходом — через футер «...».
  Возврат к трекеру — через глобальные РАЗДЕЛЫ (кнопка «← Вернуться к OKR
  Tracker» в settings становится не нужна и удаляется).
- Логика локальных секций (маршрутизация `?section=`, доступность разделов) не
  меняется — меняется только их визуальное размещение в общем контейнере.

## Изменения по файлам

- **`sidebar.js`** (новый) — `Sidebar`, `SidebarTenant`, `SidebarSections`,
  `SidebarFooter`, перенос `FeedbackNudge`.
- **`sidebar.css`** (новый) — стили `.sidebar__tenant`, `.sidebar__sections`,
  `.sidebar__footer`, `.sidebar__usermenu` и т.д. Подключается во всех shell.
- **`tracker.js`** — заменить `sidebar__header` (бургер+логотип) на
  `SidebarTenant` с `bell`, добавить `SidebarSections` под периодом, снизу
  вместо `HealthCheckInButton` — `SidebarFooter`. Колокольчик → `setHciOpen`.
- **`stub.js`** — собрать сайдбар из общих компонентов (без bell, без
  контекста), подсветить активный раздел.
- **`settings.js`, `admin.js`** — перевести свои сайдбары на общий `Sidebar`,
  локальные секции передать через `children`.
- **`system.js`** — не трогаем (superadmin, вне scope).
- **`header.js` / `header.css`** — `HeaderNavMenu` и `FeedbackNudge` больше не
  используются. `FeedbackNudge` переносится в `sidebar.js`. Файлы удаляются из
  всех shell-шаблонов (`base.html` и т.п.); сами файлы удаляются либо
  оставляются пустыми — решается при планировании после проверки всех ссылок.
- **shell-шаблоны** (`internal/http/templates/*_shell.html`, `base.html`) —
  заменить подключение `header.js`/`header.css` на `sidebar.js`/`sidebar.css`.

## Границы scope (что НЕ делаем)

- Не реализуем реальную функциональность goal-tree / activity-log (остаются
  заглушками).
- Не добавляем backend для счётчиков команд/участников тенанта.
- Не меняем логику локальных секций settings/admin/system, только их
  размещение.
- Не трогаем light-темы контентных областей и остальную вёрстку страниц.

## Тестирование

- Frontend без автотестов (React через `text/babel`), поэтому проверка —
  ручная/визуальная по каждому shell: трекер, goal-tree, activity-log,
  settings, admin. Проверить: переключение тенанта, колокольчик +
  панель Health Check-in на трекере, ссылки разделов и подсветку активного,
  футер (документация/обратная связь/меню пользователя), FeedbackNudge.
- Go-слой не меняется; существующие `go test ./...` должны оставаться зелёными.
