# Markdown support + simple WYSIWYG — Design Spec

**Date:** 2026-06-10
**Branch:** main (feature work)

---

## Цель

Добавить поддержку Markdown с простым редактором (тулбар + источник + превью) для
пользовательского текстового контента и рендерить Markdown в режиме чтения.

Затрагиваемые поля:

- описание цели (`goal.description`);
- описание KeyResult (`kr.description`);
- заметка при обновлении прогресса (`kr.note.text`);
- описание команды в админ-панели (`team.description`).

В режиме чтения эти поля отображаются как отрендеренный санитизированный HTML.

---

## Решения (зафиксировано с пользователем)

1. **Стиль редактора:** тулбар + Markdown-источник + вкладка «Превью».
   Не настоящий contenteditable-WYSIWYG (фронт — React через CDN + Babel в браузере,
   без бандлера; тяжёлая non-React библиотека рискованна).
2. **Объём Markdown:** минимальный — **жирный, курсив, маркированный/нумерованный
   списки, ссылки**. Без заголовков, блоков кода, цитат, таблиц, изображений.
3. **Рендеринг:** на клиенте, во время отображения. Хранение — сырой Markdown в
   существующих текстовых колонках. Без миграций БД, без изменений API/DTO.
4. **Ссылки:** открываются в новой вкладке (`target="_blank"`, `rel="noopener noreferrer"`).

## Архитектура

### Общий модуль `internal/web/static/markdown.js`

Новый файл, подключается как `type="text/babel"` **перед** `tracker.js` и `admin.js`
в обоих шеллах. Babel-скрипты исполняются в порядке подключения в глобальной области,
поэтому объявленные здесь функции/компоненты доступны обоим React-приложениям.

Экспортирует (в глобальной области) три сущности:

- **`renderMarkdown(text)` → string** — парсит Markdown через `marked`, санитизирует
  через `DOMPurify`, возвращает безопасный HTML. Опция `marked`: `breaks: true`
  (одиночный перевод строки → `<br>`; важно для заметок).
- **`Markdown({ text, className })`** — read-компонент. Рендерит результат
  `renderMarkdown` через `dangerouslySetInnerHTML`. Для пустого `text` рендерит `null`.
- **`MarkdownEditor({ value, onChange, rows, placeholder })`** — write-компонент:
  textarea + тулбар + переключатель «Превью».

### Санитизация (критично для безопасности)

Весь пользовательский контент рендерится **только** через `renderMarkdown`, который
прогоняет HTML через `DOMPurify` с жёстким allowlist под минимальный объём:

```
ALLOWED_TAGS: ['p', 'br', 'strong', 'em', 'b', 'i', 'ul', 'ol', 'li', 'a']
ALLOWED_ATTR: ['href', 'target', 'rel']
```

Любые теги вне allowlist (заголовки, скрипты, img, таблицы и т.п.) вырезаются,
оставляя текстовое содержимое. Через хук `DOMPurify.addHook('afterSanitizeAttributes')`:
для всех `<a>` проставляется `target="_blank"` и `rel="noopener noreferrer"`;
схемы, кроме `http/https/mailto`, в `href` запрещены (защита от `javascript:`).

Это главный инвариант корректности: описания и заметки пишут одни пользователи,
а видят другие.

### Редактор `MarkdownEditor`

- Тулбар-кнопки: **B** (жирный), *I* (курсив), `•` (маркированный список),
  `1.` (нумерованный список), `🔗` (ссылка).
- Кнопки оборачивают/префиксуют текущее выделение в textarea Markdown-синтаксисом:
  - bold → `**…**`, italic → `*…*`;
  - списки → префикс `- ` / `1. ` к каждой выделенной строке;
  - ссылка → `[выделение](url)`, для пустого выделения — `[текст](url)`.
- После вставки выделение/каретка восстанавливаются, вызывается `onChange`.
- Переключатель **«Превью»** показывает `Markdown` (read-only) поверх/вместо textarea.
- Переиспользует существующие стили формы (`form-textarea`).

### CDN-зависимости

В оба шелла (`tracker_shell.html`, `admin_shell.html`) добавляются:

- `<script>` `marked` (пиннированная версия + SRI + `crossorigin`, по образцу
  существующих React/Babel-тегов);
- `<script>` `dompurify` (аналогично);
- `<link rel="stylesheet" href="/static/markdown.css">` — стили рендера и тулбара.
- `<script type="text/babel" src="/static/markdown.js" data-presets="react">` —
  **перед** основным скриптом приложения.

`admin_shell.html` сейчас использует только инлайновый `<style>`; для него добавляется
внешний `<link>` на `markdown.css`.

### Стили `internal/web/static/markdown.css`

- `.md-content` — типографика отрендеренного контента: отступы списков, межстрочный
  интервал, стиль ссылок (цвет акцента, подчёркивание при наведении), сброс лишних
  margin у первого/последнего блока.
- `.md-editor`, `.md-editor__toolbar`, `.md-editor__btn`, `.md-editor__tab` — компактный
  тулбар и переключатель вкладок.

## Точки интеграции

### Read → `<Markdown>` (`tracker.js`)

| Место | Текущий код |
|---|---|
| Описание цели | `goal.desc` в `goal-card__desc` |
| Описание KR (строка) | `kr.desc` в `kr-desc` |
| Описание KR (модалка прогресса) | `kr.desc` в `kr-progress-desc__text` |
| Заметка прогресса | `kr.note.text` в `kr-note__text` (сейчас `white-space: pre-wrap`) |
| Описание команды (топбар) | `teamOKR.team.description` в `topbar__desc` |

При замене на `<Markdown>` ручной `white-space: pre-wrap` у заметки убирается —
переносы строк обеспечивает `breaks: true`.

### Write → `<MarkdownEditor>`

| Место | Файл | Текущий код |
|---|---|---|
| Описание цели | `tracker.js` | `<textarea>` в `GoalModal` (`form.desc`) |
| Описание KR | `tracker.js` | `<textarea>` в `KREditModal` (`form.desc`) |
| Заметка прогресса | `tracker.js` | `<textarea>` в `KRProgressModal` (`note`) |
| Описание команды | `admin.js` | `<textarea>` в `TeamEditor` (`f.description`) |

Админ отображает описание команды только в форме редактирования (списка-чтения нет),
поэтому в `admin.js` нужен только write-компонент; read-рендер описания команды —
в топбаре трекера.

## Хранение и совместимость

- Колонки не меняются: `goals.description`, `key_results.description`,
  `key_result_notes.text`, `teams.description` хранят сырой Markdown.
- Существующий plain-text контент остаётся валидным Markdown и рендерится как абзацы —
  обратная совместимость без миграций.
- API-контракт не меняется по форме: поля по-прежнему отдаются как текст. Меняется лишь
  семантика — текст трактуется как подмножество CommonMark.

## Тестирование

- Go-тесты остаются зелёными — бэкенд не меняется.
- JS-тест-харнесса в репозитории нет (браузерный Babel), поэтому редактор и рендер
  проверяются вручную через skill `verify`:
  - форматирование (жирный/курсив/списки/ссылка) корректно вставляется и рендерится;
  - ссылка открывается в новой вкладке;
  - **санитизация:** XSS-payload (`<img src=x onerror=alert(1)>`, `<script>`,
    `[x](javascript:alert(1))`) в описании/заметке не исполняется и вырезается;
  - старый plain-text контент отображается без артефактов.

---

## Вне объёма (YAGNI)

- Заголовки, блоки кода, цитаты, таблицы, чек-листы, изображения.
- Серверный рендеринг Markdown.
- Изменение схемы БД и формы API.
- Настоящий contenteditable-WYSIWYG.
