# Глобальное гамбургер-меню — дизайн

Дата: 2026-06-16

## Цель

Добавить единое гамбургер-меню (`☰`), которое ведёт себя **идентично** на всех
страницах приложения: трекер целей (`/`), настройки (`/settings`), админка
(`/admin/*`) и две новые страницы-заглушки. Меню объединяет навигацию по
разделам и аккаунт-действия в одном выезжающем слева drawer'е.

## Контекст и текущее состояние

- Три React SPA (`tracker.js`, `admin.js`, `settings.js`) рендерятся внутри
  Go-шаблонов-«оболочек» (`tracker_shell`, `admin_shell`, `settings_shell`),
  каждый из которых грузит общие `header.js` + `header.css` как `text/babel`
  **до** app-скрипта.
- Сейчас в `header.js` живёт `HeaderUserMenu` — выпадающее меню аватарки в
  правом верхнем углу сайдбара. Оно уже содержит профиль, «Документация»,
  «Настройки», «Администрирование», «Выйти». Это единственный источник правды
  для шапки (`specs/010-architecture-constraints.md:11`).
- `GET /api/v1/me` отдаёт: `id, udid, display_name, email, avatar_url,
  provider, is_admin`. Поля `role`/`team` **нет**.
- `GET /api/v1/config` (публичный) отдаёт `documentation_url`.

## Решения (подтверждены с пользователем)

1. Старый `HeaderUserMenu` (аватар-выпадашка справа) **удаляется** со всех трёх
   страниц. Все аккаунт-действия переезжают в гамбургер-меню — единый источник.
2. «Лог активностей» и «Дерево целей» — реальные роуты с shell-заглушкой
   «Раздел в разработке». Пути: `/activity-log`, `/goal-tree`.
3. Ярлык первого пункта навигации — `OKR Tracker` (ведёт на `/`).

## Архитектура

Новый глобальный компонент **`HeaderNavMenu`** в `internal/web/static/header.js`
рядом с `HeaderAvatar`. Тот же паттерн, что у `HeaderUserMenu`: глобальный
компонент, грузится до app-скриптов, единый источник правды для шапки. Стили —
в `internal/web/static/header.css`. `HeaderUserMenu` и его CSS (`.user-menu*`)
удаляются.

### Интерфейс компонента

```
HeaderNavMenu({ user, active })
```

- `user` — объект из `/api/v1/me` (передаётся страницей).
- `active` — id текущего раздела навигации (`'tracker' | 'activity-log' |
  'goal-tree'`) или `null` для admin/settings, где ни один раздел не подсвечен.
- Компонент **сам** запрашивает `/api/v1/config`, чтобы получить
  `documentation_url` — так пункт «Документация» ведёт себя одинаково на всех
  страницах (сейчас docUrl передаётся только в трекере).

### Зависимости

Только глобальный `React`, cookie (`okr_csrf_token` для logout), `fetch`.
Самодостаточен: свой рендер аватара (переиспользует существующий
`HeaderAvatar`), inline-стили + классы из `header.css`.

## Поведение и UI

Компонент рендерит **только** кнопку-триггер `☰` и выезжающую слева панель
(drawer). Логотип «OKR Tracker» и подзаголовок страницы остаются на своих
местах; `☰` встаёт слева от них в шапке сайдбара.

- Клик по `☰` открывает drawer (выезд слева) с затемнённым backdrop.
- Закрытие: клик по backdrop, крестик в шапке панели, клавиша Esc.
- Клик по пункту-ссылке переводит на соответствующий URL (обычная навигация по
  `href`, не SPA-роутинг — страницы независимы).

### Структура drawer

**Шапка панели:** иконка приложения + «OKR Tracker», кнопка-крестик закрытия.

**РАЗДЕЛЫ:**

| Пункт            | URL            | active id     |
|------------------|----------------|---------------|
| OKR Tracker      | `/`            | `tracker`     |
| Лог активностей  | `/activity-log`| `activity-log`|
| Дерево целей     | `/goal-tree`   | `goal-tree`   |

Активный пункт подсвечен (фон/цвет), если `active` совпадает с его id.

**Низ панели:**

- Карточка профиля: аватар + `display_name` + subtitle (`email`, как сейчас в
  `HeaderUserMenu`; role/team в API нет). Справа — кнопка-шестерёнка → `/settings`.
- Лейбл **АККАУНТ**, затем:
  - `Документация` → `documentation_url` (новая вкладка), только если непустой.
  - `Администрирование` → `/admin`, только если `user.is_admin`.
  - `Выйти` → `POST /logout` с заголовком `X-CSRF-Token` (логика переносится из
    удаляемого `HeaderUserMenu`), затем редирект на `/login`.

## Страницы-заглушки

Новый общий Go-шаблон `internal/http/templates/stub_shell.html` (`{{define
"stub-shell"}}`) и маленький `internal/web/static/stub.js`. Шаблон грузит те же
общие скрипты (`header.js`/`header.css`) + `stub.js`. `stub.js`:

- запрашивает `/api/v1/me`,
- определяет раздел по `location.pathname` (`/activity-log` → `activity-log`,
  `/goal-tree` → `goal-tree`),
- рендерит сайдбар с `HeaderNavMenu user={me} active={section}` и контентную
  область с сообщением «Раздел в разработке».

### Роуты

В `internal/http/server.go` рядом с `trackerShell`, в той же группе доступа
(любой авторизованный пользователь, как `/settings`):

```
r.Get("/activity-log", stubShell)
r.Get("/goal-tree", stubShell)
```

где `stubShell` исполняет шаблон `stub-shell`.

## Интеграция в страницы

В `tracker.js`, `admin.js`, `settings.js` и в `stub.js`:

- удалить использование `<HeaderUserMenu .../>`;
- в начало шапки сайдбара поставить `<HeaderNavMenu user={me} active="…"/>`:
  - `tracker.js` → `active="tracker"`;
  - `admin.js` → `active={null}`;
  - `settings.js` → `active={null}`;
  - `stub.js` → `active={section}`.

## Обновление specs (в этом же change set)

- `specs/010-architecture-constraints.md:11` — заменить описание `HeaderUserMenu`
  на `HeaderNavMenu` как новый единый источник правды для шапки/навигации.
- `specs/030-user-flows.md` — обновить упоминания «аккаунт-виджет в правом
  верхнем углу» (разделы 0/«Выход», ~161, ~252): аккаунт-действия теперь в
  гамбургер-меню. Добавить раздел про глобальную навигацию и две страницы-заглушки
  (`/activity-log`, `/goal-tree`).
- Не трогать несвязанные specs.

## Тестирование

- Go-тест: новые роуты `/activity-log` и `/goal-tree` возвращают `200` и отдают
  shell-заглушку (по аналогии с существующими тестами роутов shell).
- JS не покрыт юнит-тестами в проекте — следуем существующему подходу.

## Вне scope (YAGNI)

- Реальная функциональность лога активностей и дерева целей.
- Поля role/team в профиле (нет в API; не добавляем).
- SPA-роутинг между разделами (страницы остаются независимыми).
