# Дизайн: избранные команды в сайдбаре

Дата: 2026-07-08
Статус: согласовано, готово к плану реализации

## Проблема

Иерархия команд в сайдбаре может быть большой и вложенной. Пользователю
неудобно каждый раз искать важные для него команды в дереве. Нужна возможность
закрепить произвольные команды повыше — «избранное».

Ограничения от заказчика:

- Избранное работает **через состояние на клиенте** и **не создаёт
  дополнительной нагрузки на бек** (никаких новых запросов/эндпоинтов/таблиц).
- Если избранная команда пропала из ответа бека — это **не должно приводить к
  крашам или ошибкам**.

## Границы (scope)

- Только фронтенд: `internal/web/static/tracker.js` + `tracker.css`.
- Изменений в доменной модели, API-контракте, БД, seed и специях
  (`specs/*.md`) **не требуется** — фича полностью клиентская.
- Backend не трогаем.

## Решения (согласовано)

- Порядок в блоке «Избранное» — **по порядку добавления** (новые в конец).
- Иконка-звезда на строках дерева — **всегда видна** (контурная у обычных,
  заполнённая у избранных).

## Хранение

Личное предпочтение, живёт в браузере пользователя. Новый per-user ключ
`localStorage`, по образцу существующих (`TREE_EXPANDED_KEY`,
`SETTINGS_SIDEBAR_KEY`):

```
okr_fav_teams:${uid}  ->  JSON-массив id команд в порядке добавления
```

- Хранится **глобально**, не по периодам: избранное — это про команду, а не про
  период.
- Читается один раз в state приложения, пишется при каждом изменении.

Чистые функции (по образцу `readTreeExpanded` / `writeTreeExpanded`):

- `readFavorites(uid): (string|number)[]` — вернуть массив id; при
  отсутствии/битых данных — `[]`. Id команд приходят из API числами, поэтому
  фильтр принимает и числа, и строки (иначе избранное терялось бы при перезагрузке).
- `writeFavorites(uid, ids): void` — сериализовать, `try/catch` на quota /
  private mode (как у существующих writer'ов).
- `toggleFavorite(ids, id): string[]` — чистая функция: если `id` есть —
  удалить, иначе добавить в конец. Возвращает новый массив (иммутабельно).

## Устойчивость к пропаже команды

Блок «Избранное» строится из полной `hierarchy`:

1. Плоско собрать все узлы дерева (id → node).
2. Пройти по `favorites` **в порядке хранения**, для каждого id взять узел из
   мапы; если узла нет — **пропустить** (не рендерить).
3. Отрисовать полученный список.

Свойства:

- Неизвестные id **молча игнорируются** при отрисовке, но **остаются в
  хранилище** — если команда снова появится в ответе (другой период, вернулся
  доступ), она снова покажется в избранном. Тот же принцип, что уже применяется
  для `TREE_EXPANDED_KEY` («unknown ids are ignored»).
- Никаких исключений: пустой/битый JSON → `[]`; отсутствующий узел → пропуск.

Важно: блок «Избранное» смотрит на **полную** `hierarchy` (до
`filterTreeForSidebar`), поэтому избранная команда показывается даже если она
отфильтрована пользовательскими настройками сайдбара.

## UI / компоненты

Внутри `sidebar__tree` появляется явная структура блока команд:

```
КОМАНДЫ                       ← лейбл секции (sidebar__section-label)
  ★ ИЗБРАННОЕ · N             ← подзаголовок; N = число видимых избранных
    <плоский список избранных команд>
  ВСЕ КОМАНДЫ                 ← подзаголовок
    <дерево SidebarNode, как сейчас>
```

- Если избранных (видимых) нет — весь под-блок «Избранное» **скрыт целиком**
  (компактность, никакого пустого заголовка).
- `N` — количество избранных, реально присутствующих в текущей `hierarchy`.

### Звезда на строках дерева

В `SidebarNode` в строку (`sidebar-node__row`) добавляется иконка-звезда между
названием и процентом прогресса (порядок: имя → ★ → %; когда `%` нет — звезда
крайняя справа, как на скрине):

- Всегда видима.
- Контурная (`☆`) у не-избранных, заполнённая (`★`) у избранных.
- Клик по звезде: `stopPropagation` + `onToggleFav(node.id)` — не выбирает
  команду.
- Заполненность определяется по `favorites.has(node.id)` (для O(1) в рендере в
  `SidebarNode` передаём `Set` избранных).

Пропсы, протянутые вниз по дереву: `favSet` (Set id) и `onToggleFav(id)`.

### Блок избранного

Переиспользуем тот же `SidebarNode` — **без нового компонента**:

```
favNodes.map(n => <SidebarNode node={{ ...n, children: [] }} depth={0}
  favSet={favSet} onToggleFav={onToggleFav} ... />)
```

- `children: []` → нет тоггла раскрытия и рекурсии → строка плоская.
- `depth: 0` → без отступа.
- Звезда у всех заполнена (они по определению в `favSet`).
- Клик по строке = выбор команды (`onSelect`), как в дереве.
- Прогресс показывается по той же логике (`prog != null`), что и в дереве.

## Стили (tracker.css)

Новые классы, консистентно с существующими `sidebar__*` / `sidebar-node__*`:

- `sidebar__section-label` — серый uppercase лейбл «КОМАНДЫ».
- `sidebar__subsection-label` — лейблы «ИЗБРАННОЕ · N» и «ВСЕ КОМАНДЫ»
  (компактные отступы).
- `sidebar-node__star` — иконка-звезда: приглушённый цвет у контурной, акцентный
  (жёлтый) у заполнённой; hit-area достаточного размера, `cursor: pointer`.

Отступы компактные, чтобы блок команд занимал минимум вертикали.

## State в App()

- Новый state `const [favorites, setFavorites] = useState(null)` — сентинел
  `null` означает «ещё не загружено из storage» (нужен, т.к. `me` грузится
  асинхронно).
- Load-эффект: `if (me && favorites === null) setFavorites(readFavorites(me.id))`.
- Write-эффект: `if (me && favorites !== null) writeFavorites(me.id, favorites)`.
  Гард по `null`-сентинелу (а не по ref) обязателен: ref флипается синхронно и
  write-эффект в том же commit затёр бы сохранённое значение пустым массивом.
- `onToggleFav = id => setFavorites(f => toggleFavorite(f, id))`.
- Производные (в рендере, без лишнего state): `favArr = favorites || []`,
  `favSet = new Set(favArr)`, `favNodes = collectFavNodes(hierarchy, favArr)` —
  узлы из полной `hierarchy` в порядке `favArr`.

## Консистентность и многоинстансовость

- Данные только в `localStorage` конкретного браузера пользователя. Развёртывание
  в K8S на много инстансов роли не играет — состояние не ходит на бек.
- Пользовательское ожидание: избранное — личная настройка «этого браузера».
  Синхронизация между вкладками (storage-событие) и между устройствами — **вне
  scope** (YAGNI). При необходимости добавляется позже без изменения контракта
  хранения.

## Тестирование

- JS-тест-раннера в репозитории нет (`package.json` отсутствует). Логика
  favorites вынесена в чистые функции (`readFavorites`, `writeFavorites`,
  `toggleFavorite`, сборка `favNodes`), чтобы при появлении раннера её можно было
  покрыть юнит-тестами без рефакторинга.
- Ручная проверка сценариев:
  1. Добавление/удаление избранного звездой в дереве — строка появляется/исчезает
     в блоке «Избранное»; звезда синхронно меняет вид.
  2. Порядок в блоке = порядок добавления.
  3. Перезагрузка страницы сохраняет избранное.
  4. Смена периода: избранная команда без данных в периоде скрыта из блока, но
     возвращается при возврате в период, где она есть.
  5. Битый/отсутствующий id в хранилище не ломает рендер.
  6. Пустое избранное → блок «Избранное» скрыт.
